# ADR 039 — Observed root frames in stable update loops

## Context

Round 17's deferred root protocol cut allocating filters to 76–79 ms but adds a
root-state observation to every checked replacement. Published 16 MiB medians:
map 37.94 → 47.28 ms, transform 37.90 → 44.83 ms. Root counts must still match
eager accounting at every allocation, quota check, uniqueness check and collection.
This decision depends on the independent ADR 038 audit passing first.

## Decision

Admit a compiler-only observed-frame replacement path for retained, flat sequence
loops with one loop-carried replacement and no other allocating/root-writing work.
Every dynamic state must be identity-carried except the replaced state. Its body
result must be the proved replacement, using the existing single-use chain proof.
Other instructions must produce non-dynamic values and satisfy the body-derived
borrowing summary; nested regions/loops and record states are initially excluded.
No calls with allocating/effectful summaries are admitted. Borrowing callees use
no root frame or slot writes; scalar traps and ticks remain in source order.

Reconcile once after preheader roots are installed. Recycle the replaced state's
one retained slot. After each replacement, compare the returned pointer with the
slot: if unchanged, no store or reconciliation is necessary; if copying changed
it, store and reconcile immediately. Thus the next iteration starts with exact
counts even when an external alias forces a copy. No pointer identity, uniqueness,
quota availability or bounds assertion is assumed statically. All replacement
checks and copying paths remain; only the redundant pre-update reconciliation
is skipped. Exit/finish returns to the ordinary root protocol. This is not an
unchecked element-access path or write-vectorization claim.

Do not admit concat, record-buffer updates, snapshot chains, allocating lazy arms,
or multiple replacements under this first proof. Their observations remain intact.
Ordinary profiles and immutable-value semantics are unchanged.

## Forecasts (before implementation/measurement)

Same machine, same rotating whole-process controls, O2, at least 25 repetitions:

| Control | Round 17 median ms | Forecast ms |
|---|---:|---:|
| Materialized map 16 MiB | 47.28 | 32–39 |
| File transform 16 MiB | 44.83 | 32–39 |
| Hand/std filter 16 MiB | 75.76 / 79.44 | within 10% of same-session baseline |
| Readonly scan | previous 7.5–10.5 | unchanged within noise |

Targets are <=37.9 ms map/transform; misses must be published. Predictions are
judgments, not measurements. Alias, quota, bounds and byte failures require
reference/native O0/O2 and sanitizer checks, including the slow copying branch.

## Alternatives

Remove observations globally: unsound. Assume last use means physically unique:
unsound with callers/record descendants. Add an unsafe profile: rejected.
Runtime dirty-flag tuning alone has already regressed shape-dependent workloads.
General static slot dataflow could cover more shapes but is a separate proof.

## Consequences

A new private runtime entry point depends on a compiler proof; it is not exposed
to programs/plugins. Future callers must establish and maintain the exact-frame
invariant. The generic checked update remains available for all unproved shapes.

## Status

Accepted after the independent Round 17 audit passed; committed before implementation.

## Addendum: allocation-site stability (preregistered before compiler change)

The first implementation meets map/transform targets, but source-sort medians are
4–9% higher in repeat campaigns. An external rebuild with identical text/data
sections, bind fixups and function starts also slows down. Added phase clocks
restore parity (five measured repetitions), so the evidence excludes neither
layout nor allocator effects. No private-global grouping or slot-alignment tweak
was accepted from these probes.

Both processes use Apple's xzone allocator and have identical final zone counts.
Its [documented type fallback](https://github.com/apple-oss-distributions/libmalloc/blob/main/src/malloc_type_internal.h)
derives the descriptor hash from a return address; [type buckets](https://github.com/apple-oss-distributions/libmalloc/blob/main/doc/xzone_malloc.md)
therefore provide a plausible source of binary-sensitive costs. This is a
mechanism supported by source, not a complete attribution of the observed gap.
An external prototype gives arena sequences one explicit opaque descriptor, with
no layout promises: five measured medians before/after are 1416/1456 ms, versus
unannotated 1433/1536. This exploratory result is not a preregistered success.
An intentionally invalid standalone C probe confirms ASan intercepts the typed
allocation API and catches a one-byte overflow. No production NIL finding occurred.

Conditional decision: use a stable descriptor for the common NilSequence header
allocation family, including its variable tail, on macOS SDK14+ with weak-linked
malloc_type_malloc/realloc. Older SDKs, older operating systems and other platforms
retain malloc/realloc. Descriptor summary bits stay zero: it asserts no pure-data
or pointer-layout fact. Allocation size, ordinary free, null handling, quota checks,
root synchronization, relocation and trap order are unchanged. This adds no HIR
operation, dependency, public setting or source profile. Sanitizer interception
and the portable fallback must both remain checked.

Before the compiler change, forecast the weak-linked candidate at 1M source sort:
1400–1490 ms and within 3% of the contemporaneous Round17 baseline; 64k within5%.
Other 25-repeat controls must stay within observed noise, map/transform <=37.9 ms,
push within10% of concat. Misses stay visible. First run at least25 repetitions
of the external weak-linked prototype; implement only if this supports recovery.
Then repeat every compiler/sanitizer/fuzz/corpus gate and the whole control matrix.
If the allocator annotation fails, retain the open performance gate; do not tune
descriptor numbers or discard unfavourable campaigns.

### Follow-up disposition

Accepted after the external weak-linked candidate passed its preregistered
25-repeat test, before runtime implementation commit `398156d`. Final production
1M source sort is 1437.751 ms against baseline 1457.557; 64k is 73.151 against
76.543. Map/transform targets and push parity hold. Debug/release CI, three full
fuzz seeds, corpus and both normal/portable sanitizer paths were rerun after the
change. See the Round18 report for all samples/receipts and small non-target drift.
No global grouping or slot-alignment experiment was adopted.
