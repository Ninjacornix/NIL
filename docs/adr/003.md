# ADR-003: Semantic HIR boundary

## Context

The brief requires multiple source frontends to share semantics. Research sometimes uses “HIR” for both generated text and internal representation.

## Decision

Use HIR exclusively for the typed in-memory semantic representation. The proposed M1 HIR has functions, typed parameters/results, immutable instruction values and one return. Source labels resolve to internal IDs; source spans are optional metadata.

## Alternatives

Reuse the AST as HIR; put source keywords in evaluator logic; implement a full MLIR dialect immediately.

## Consequences

Alternate frontends can construct and validate HIR without depending on lines-v0. Shape can evolve through versioned proposals; no stable serialized ABI is promised.

## Status

Accepted boundary; proposed M1 shape.
