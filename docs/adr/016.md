# ADR 016: External benchmark suite with a pinned submodule

## Context

Paired corpora, tokenizer tools, generated data, and timing helpers inflated
compiler changes. Some compiler tests depended on benchmark fixture paths.

## Decision

Maintain benchmark sources and reviewed reports in `Ninjacornix/NIL-benchmarks`.
Expose that repository at `benchmarks/` as a pinned Git submodule. Fetch it only
for benchmark work. Keep correctness fixtures under `tests/fixtures` in NIL.
Move timing/oracle helpers outside the compiler workspace; benchmark builds
link against the selected local compiler libraries using a locked helper manifest.
Record compiler and suite revisions independently. Keep raw artifacts external.

## Alternatives

A directory in the compiler repository retains shared churn. An unpinned clone
makes reproduction ambiguous. ZIP archives suit datasets, not evolving tools.

## Consequences

Normal compiler builds/tests work without recursive cloning. Benchmark users run
`git submodule update --init benchmarks`. Suite changes are published first, then
NIL updates its pointer. CI separates compiler quality from suite smoke checks.
Already published Git history is preserved; removal does not shrink old objects.

## Status

Accepted; repository and submodule choice explicitly authorized by the maintainer.
