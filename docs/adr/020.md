# ADR 020 — Interprocedural scalar borrowing

## Context

Scalar lazy regions are cheap, but calls and nested loops invalidate the local
root-retention proof. A small scalar helper inside a 16 MiB scan costs roughly
156 ms against 12 ms inline. LLVM inlining alone cannot remove bookkeeping that
is already observable to allocating callees.

## Decision

Compute a syntax-independent HIR summary over validated programs: returns i64/bool,
performs no dynamic allocation, produces no sequence intermediates, and has no
host effects. Scalar arithmetic, comparisons, checked index/length and decimal
parse qualify. Traps are allowed; this is **not** a promise of nontrapping execution.
Calls qualify only if their targets qualify. Ifs keep both arms and require both
summaries. Loops require qualifying conditions/finish, qualifying body instructions,
and identity-carried non-scalar state; nested qualifying loops are allowed.

Use a greatest fixed point: begin with scalar-returning candidates, then repeatedly
remove functions with a disallowed operation or disqualified callee. Recursive
and mutually recursive groups survive only if every reachable operation satisfies
the proof. No annotation, source spelling or inlining decision enters this analysis.

Borrow sequence parameters and region inputs without redundant shadow-stack roots
when this summary holds. Arena collection/reallocation cannot occur during the
borrow; no sequence pointer can escape through its scalar result. Keep semantic
last uses/capture unions unchanged. Keep original CFG edges, ordered calls,
checks, instruction ticks and call-depth guards. Retained replacement loops may
call qualifying helpers; their existing last-use replacement proof is unchanged.

## Alternatives

Relying on the LLVM inliner would leave large/recursive helpers unproved.
Marking callees LLVM readnone/speculatable would conceal traps and resource checks.
General allocation/effect summaries with escaping sequence results would require a
broader lifetime proof; they remain conservative here. Benchmark-only noinline
attributes demonstrate the boundary without adding a language feature.

## Consequences

Nonallocating scalar callees and nested identity loops need no sequence root frame,
even at O0. LLVM may subsequently inline/vectorize, but the root removal precedes it.
Allocations (including byte literals), replacements, sequence-valued instructions
and host effects disqualify function borrowing. Sequence-returning callees and
allocating recursive frames keep roots. Safe subregions can still borrow inside
an otherwise conservative function. Unproved allocating loop transfers remain.
The initial fixed point can require O(functions² × instructions) in a long rejecting
call chain; an SCC/worklist implementation is a future scalability improvement.
The C runtime remains the single source of bounds/byte/parse/quota semantics.

## Status

Accepted implementation experiment. No language, profile, quota or ABI changes.
