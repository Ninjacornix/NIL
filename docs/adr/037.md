# ADR 037 — Standing, isolated generation tracking

## Context

Source-token counts are not generated or repair tokens. Frozen Ollama studies found
NIL 0/24, Python 11/24; few-shot improved parsing but not solves. Reuse
`benchmarks/generation/application` extraction, repair conversations, oracle,
reference/native O0/O2 paths, plus the corpus's unchanged task contracts/expected
values. Extend with a transport and standing matrix, not another eval service.
Compiler/runtime/std/corpus sources are out of scope.

## Decision (preregistered before implementation/inference)

Use exact `claude-sonnet-5-5`, effort **high**, Claude CLI print/stream JSON. No
Codex/GPT model under test or fallback. Installed CLI initially 2.1.291; auth is
Claude.ai subscription, no API key. Record resolved executable/version, every
argument and environment-variable *names/nonsecret values* per request.

Each stateless request starts in a fresh empty directory outside both repositories.
An OS sandbox denies repository/user-document reads. Tools must be empty; strict
empty MCP, disabled hooks/skills, replaced fixed system prompt, no persistence,
no resume. Prefer bare if API-key auth exists; OAuth uses safe/restricted mode,
empty setting sources and explicit disableAllHooks. Verify offline denial probes,
then require stream init tools/MCP empty and zero tool_use/tool_result blocks.
Any violation stops live inference, not merely invalidates one candidate. Retained
OAuth/keychain access is authentication authority, not repository authority. No
sandbox claim about NIL itself. Do not log credentials or debug auth traffic.

Three arms share task contracts and oracles: Python without a language spec; NIL
with exact EXPR_V5.md; NIL with that spec and the unchanged four fixed exposure
examples. The published spec itself contains examples: “spec-only” does not mean
zero example exposure. Common task/file interface, repair discipline and caps.

`split.json` selects **24 held-out tasks**: 8 original byte/file, 12 external,
4 algorithms; DEV has 6. Rank supported, self-contained contracts by SHA256 of
`NIL-R15-v1/<id>` within domain, excluding the four fixed examples and any answer
already in the mandatory spec. Canonical-JSON placeholders lacking a self-contained
contract are explicitly excluded, not silently given hidden fixtures. This limits
generality. No selection by source length, observed success or token result.
Only one frozen DEV task, one replicate across arms, confirms the pipeline; no
prompt tuning after that. Other DEV tasks are reserved, not scored. Held-out
statements/solutions cannot appear as context/examples for another task. The
current task's contract is the sole allowed held-out statement. Corpus solutions
are never inserted into prompts/backend requests; leakage auditing may read them
only to reject a match.

Two independent replicates/task/arm, no controllable temperature/seed. Three
attempts including the initial one (two repairs), 512 backend output tokens per
attempt and 1,536 per trial, preserving frozen limits. Set the CLI's installed
`CLAUDE_CODE_MAX_OUTPUT_TOKENS` control and reject/report overruns. Effort/thinking
cost is included in reported output usage, not guessed from source. Maximum 432
held-out + 9 DEV requests, plus at most 2 input-accounting calibrations = **443**.

Total notional spend cap **USD 50**, including DEV/calibration, regardless of
subscription billing. Reserve USD 1 for each next request and pass
`--max-budget-usd 1`; stop if that reservation cannot fit. CLI budget enforcement
may check after an API call; report any overshoot honestly, never hide it. Missing
usage/cost, infrastructure failure or model unavailability stops; no retry/model
substitution. After DEV, commit a remaining-cost forecast from observed usage
before held-out starts. A forecast above remaining budget permits only an explicitly
partial run; the cumulative/reservation checks still govern every request.

Count input, cache creation, cache reads and output from backend usage; full input
is their input-component sum. Preserve cl100k/o200k source screens separately.
If live access works, two fixed prefix-only accounting requests measure the marginal
spec input (otherwise unknown): identical prompt with/without the exact spec, no
held-out tasks or solutions. A deployment scenario charges that measured prefix
once per trial/session rather than once per attempt; subtract only repeated spec
charges, not output/repair tokens or example charges. Report its assumptions,
including token-boundary/framing differences. Actual provider cache usage and USD
cost remain separate real measurements; amortized scenarios are not actual bills.
Never subtract tiktoken estimates from provider totals. Undefined TCR at zero
solves, unknown accounting if usage missing; do not replace either with zero.

Track parse/type/native O0/O2/semantic results, first-pass success, trap, budget,
isolation/infrastructure and syntax-feature failures. Reuse real diagnostics for
repairs; no golden answer/fixture in feedback. Report per task/arm and aggregate,
failure-inclusive tokens, cost/time, task-cluster paired bootstrap (2,000 samples,
fixed reporting RNG). This is a tracking vector, never a weighted score or gate.

Forecast before live requests: Python parse 98%, solves 70%; NIL spec parse 70%,
solves 25%; few-shot parse 85%, solves 35%. NIL/Python output TCR ratio 1.5–3,
full total TCR 10–40. Judgment forecasts, not evidence. Legacy short output caps,
public tasks/model pretraining and only 24 tasks limit inference. Amortization
forecast remains unknown until backend prefix accounting exists.

## Alternatives

Keep Ollama for frozen historical replication; no replacement digests or new
model substituted this round. Dynamic tool-enabled agents violate isolation.
Third-party eval services/new Python packages add no needed capability. Tiktoken
cannot impersonate model usage. Rewriting sparse task contracts after results
invalidates preregistration; reserve that for a later experiment.

## Consequences

CLI/version/split/prompt/oracle/source hashes and UTC request times bind each run.
Raw requests/responses live outside Git; publish hashed archives and summary JSON/
Markdown. No credentials, generated candidates or raw transcripts in commits.
If isolation/auth/model access fails, deliver definition, tests and labelled mock
end-to-end evidence plus exact maintainer command; no invented NIL/Python finding.

## Status

Accepted preregistration; exact plan/split in `benchmarks/generation/standing/`.
Commit before implementation/live requests. Local commits only; no push.

## Round 15b addendum — subscription transport (preregistered)

The Round 15 EPERM was a harness defect, not evidence that this machine cannot
run the model. The CLI's own state ignored TMPDIR. Use one private temporary root
with sibling `cwd/`, `state/`, and `home/` directories; set CLAUDE_CODE_TMPDIR to
state and keep cwd empty. Allow writes only inside that temporary root. Deny
repository and keychain reads explicitly; do not retain the real home/config or
keychain exception. Both preflight and requests use this exact layout/profile.
Preflight denies all network access, proves repository/keychain-file denial and
checks initialization for the exact model, tools=[] and mcp_servers=[]. Inspect
all stream blocks for tools/hooks, including on errors. CLI version/flags and
nonsecret environment values remain recorded. No live requests in this round.

Authentication is subscription-only: read NIL_CLAUDE_OAUTH_TOKEN_FILE (default
~/.config/nil/claude-oauth-token) before sandboxing; require a regular, privately
owned file with no group/other permissions. Pass its content only in
CLAUDE_CODE_OAUTH_TOKEN, never argv. Do not use --bare or API-key fallback. Keep
--safe-mode --restricted and all previous isolation controls. Sanitize exact
secret values before any artifact, error or diagnostic is persisted. Redact API
keys too if present in the parent environment, even though they are not forwarded.
Missing/insecure token files fail closed before CLI startup. A planted-token test
scans every artifact from an entire mock campaign, not only request metadata.

Subscription total_cost_usd is **notional**, not a subscription invoice. The USD50
cumulative cap and USD1 next-request reservation/CLI budget still apply, including
DEV and accounting probes. No usage or prices have been measured: the 443 maximum
invocations would reserve USD443 in the worst case, well beyond USD50. Completing
the matrix is not promised. A committed forecast from actual DEV usage remains a
prerequisite for held-out; do not invent a dollar forecast from unknown pricing.
The enlarged token envelope increases worst-case exposure; CLI budgeting can check
after a call, so retain/report any actual notional overshoot.

A recognized backend rate/usage-window limit pauses the campaign, not the trial.
No automatic retry. --resume uses the same directory, frozen matrix order,
messages, attempt index and remaining trial budget. Persist atomically after each
completed attempt and before each invocation. A crash with an unresolved in-flight
request cannot safely resume (usage/cost unknown); fail closed rather than duplicate
it. Completed attempts, diagnostics and costs are never regenerated or recharged.
Explicit rate pauses are logged separately with known usage/cost (unknown stays
unknown); any observed tokens count toward the trial cap and failure-inclusive
accounting, but not parse/solve denominators. Cost unknown after an invoked request
prevents resume under a hard cap. Zero-usage pre-request limit rejection must have
explicit backend cost/usage evidence; absence does not imply zero.

Resume validates plan/split/spec, compiler and benchmark revisions, CLI version,
original prompt hashes and journal integrity before another request. Rate pauses
in input-accounting probes resume at the exact probe too. Record pause/resume UTC
times. Keep max 3 completed generation attempts/trial; interrupted, explicitly
resumed transport invocations have their own ledger and count toward the global
443-invocation bound. This prevents rate windows creating an unbounded campaign.
No prompts, task selection, repair budgets, oracles, models or forecasts are tuned.

Status: accepted subscription-transport amendment; output-cap amendment below
must be committed together with experiment.json before dependent implementation.

### Output-cap correction (Round 15b)

Use **8,192 backend output tokens per request and 16,384 per trial**, identical
across all arms, including reasoning tokens in backend usage. High effort can use
512 tokens in thinking before emitting any source. No live generation request has
run: this corrects the experimental design, not tuning after results. The previous
512/1,536 limits are superseded; three completed attempts remain unchanged.

The worst-case generation envelope is 147 trials * 16,384 = 2,408,448 output
tokens; two accounting requests add at most 16,384, for **2,424,832**, versus the
old 226,816 envelope (443 * 512). This is a 10.69x output-envelope increase,
not a prediction of actual usage or spend. Input/spec/repair costs are additional.
No actual DEV usage or model pricing is available to support a new dollar point
estimate: USD443 of worst-case request reservations exceeds the unchanged USD50
cap. Record the new envelope and that budget risk now; after real DEV, recompute
mean/max notional cost forecasts and commit them before held-out. Solve/parse
forecasts remain those of Round 15; no observations justify changing them.
