# ADR 046 — Ordinary memory failure and optimizer freedom

## Context

**Maintainer decision, 2026-10-08:** memory exhaustion is an ordinary environment
failure, not deterministic language behavior. This supersedes ADR 045, including
its 40-byte descriptor plan, and the quota-equivalence obligations of ADRs 017,
033, 036, 038, 039, 043 and 044. Their value, effect, alias, arithmetic and lifetime
obligations remain. The committed fail-fast streaming reader remains ordinary
implementation behavior; its exact resource boundary is no longer a contract.

Starting main: `50a71e4` (read fix `b23d0e9`); benchmarks: `7d30da2`.
Uncommitted ledger work was stashed as `superseded by ADR 046`, not committed.
Historical studies stay intact. Branches remain `feat/core-memory` and
`exp/core-memory`, local only. No frozen natural source or held-out task changes.

## Decision

### Memory and differential outcomes

Allocate when needed; free unreachable storage using the existing arena and
reference value lifetimes. There is **no logical-version ledger**, no semantic
capacity charge and no reservation as though an update copied. Reuse may reduce
memory as well as time. Allocation strategy, capacity and resource-failure
instruction are implementation details; immutable values remain the semantics.

Retain a configurable safety guard for execution-managed dynamic storage, default
**256 MiB** from Round 21's 18.47 MiB worst admitted RSS / 52 MiB old prospective
reservation. It is not a process RSS limit or sandbox. Rust `Limits` and native
`Options` expose `memory_bytes`; CLI `--memory-limit BYTES|NMiB` configures v5
run/build. Zero disables the guard; checked size arithmetic and allocation failure
handling remain. Tests/fuzz explicitly select 64 MiB or smaller values. Other
profiles and the default source profile remain unchanged.

Exceeding the guard reports E013 cleanly. Reference storage estimates and the
native arena need not exhaust it at the same instruction. Real OS allocator
failure is also environmental; this does not claim recovery from Rust's global
allocator abort or OS process termination. No memory-safety violation becomes a
resource outcome. Invalid sizes cannot overflow allocation/index arithmetic.

Differential runs compare codes **and spans**, output, defined arithmetic,
iteration order and host effects exactly, except a clean E013 on either path is
**INCONCLUSIVE**, never a solve or a successful equivalence check. Count these
per seed/program/backend and archive both outcomes. Native signals, malformed
failure output, build/infrastructure errors and sanitizer findings remain failures,
even if the other path reports E013. Frozen E013 assertions are not rewritten:
the verifier identifies and lists inconclusive checks. The fault audit keeps its
fourteen cases and prefix/error receipts; E013 cases are inconclusive, not exact
quota-precedence evidence. Non-E013 I/O failures still compare exactly.

### Optimizer admission (B2)

Multiple-update and intervening-allocation barriers whose sole reason was
reservation equivalence can disappear. G2 still needs a general SSA/dependency
analysis and guarded nontrapping snapshots for every original read. Effects and
traps execute in original order; unsupported or escaping observations copy.
Use the full variant matrix: reordered operands, bindings/inline, helpers,
nested selected/unselected arms, reads before/after updates, recursive callees,
record children and aliases. No benchmark-shape recognizer.

G1 is **not automatically proven**. Last-use through callees/returned aliases and
child reachability still requires provenance. Ship it only after a separate
preregistered fixed-point proof and commit; otherwise explicitly defer it.

### Std swap/pop (B3)

Compiler-versioned NIL source, no new intrinsic: `!swap(seq,i,j)` and `!pop(seq)`
for Buffer/Bytes. Record buffers only if their child proof applies without extra
capability. Measured tiktoken 0.12.0, cl100k/o200k respectively:

| Spelling | cl100k | o200k | Equivalent | Tokens in either |
|---|---:|---:|---|---:|
| `!swap(a,b,c)` | 6 | 6 | `a[b:a[c]][c:a[b]]` | 9 |
| `!pop(a)` | 4 | 4 | `!slice(a,0,#a-1)` | 10 |
| `!remove_last(a)` | 5 | 5 | same slice | 10 |

Swap evaluates arguments left-to-right; inside it check/read j, then i, before
writing, matching the functional swap's first possible bounds failure. Cache both
original values. Live aliases keep copying. Pop returns the shortened sequence,
not the removed element; empty input is E012. A final-use slice may reuse owned
storage with checked bounds and child handling; no views. Library failures retain
specified source provenance, not invented caller spans. Placement follows ADR 035;
backend storage proofs do not become new library intrinsics.

### Depth and stack safety (B4 admission)

Default v5 call depth **1024**, configurable CLI `--call-depth N` and Rust API;
explicit 256 in legacy tests/fuzz. Zero denies entry with E008; no unbounded-depth
option is promised. Reference frames remain heap allocated. Native v5 enforces
the configured depth even with unbounded instruction fuel.

Native stack-headroom protection must run **before** a potentially large callee
prologue. Prefer a private execution stack sized from configured depth and a
verified generated machine-frame bound, with a pre-call headroom guard. It must
not depend on a guessed LLVM alloca sum. An alternate-stack fault handler alone
cannot classify arbitrary memory bugs as stack exhaustion and is insufficient.
Do not ship B4 without deep/large-frame O0/O2 and sanitizer evidence that the
configured limit is reachable and stack exhaustion exits with clean E008. If
that bound cannot be established, stop at the last completed step and report it.
This is implementation machinery, not language concurrency.

## Alternatives

Deterministic logical ledger/reserve-as-if-copying: rejected by the maintainer;
its complexity exists to preserve a resource policy that is no longer wanted.
No safety guard: offered only explicitly as zero, not the default. Keep a fixed
64 MiB language ceiling: rejected. Ignore all diagnostic mismatches: rejected;
only clean E013 is inconclusive. Classify native crashes as E013: rejected.
Replace alias proofs with runtime uniqueness alone: rejected; physical roots do
not prove a later old read can see mutated data. Heap-copy to preserve quota:
rejected; copy only to preserve actual observable values.

## Consequences

Resource results change deliberately. Memory efficiency becomes an optimization
benefit. Guard estimates and strategies can differ across backends. Deterministic
outputs and bug diagnostics remain load-bearing. Historical quota studies do not
establish the new memory contract. CLI/Rust option additions and changed defaults
are documented API changes. Test count changes are itemized, not hidden.

## Status

Accepted maintainer memory decision and preregistration before compiler changes.
B1–B4 implementations remain separately gated; no forecast is a measured result.
