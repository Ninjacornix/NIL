# ADR-009: Diagnostic contract

## Context

LLM repair and human debugging need different renderings of the same compiler error. Research wire formats are examples rather than finalized protocols.

## Decision

Keep diagnostic code, phase, optional byte span, message and optional expected/actual values in an internal struct. Begin with deterministic first-error reporting and a compact text renderer. Add JSON and structural patches only when required by benchmark tooling.

## Alternatives

Ad hoc strings only; full JSON/RPC protocol now; multi-error recovery in M1.

## Consequences

Codes and span semantics can be golden-tested. No source-level fake coordinates for backend errors. Codes are provisional until versioned.

## Status

Proposed M1 contract.

## M1 implementation update

The user subsequently authorized M1 implementation. The reference interpreter,
line parser, typed HIR and diagnostic contract are now implemented and tested.
These are M1 policies; final syntax, production backend and expanded types remain
unresolved. The earlier setup-only delivery constraint no longer blocks M1.
