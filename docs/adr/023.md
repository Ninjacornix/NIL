# ADR 023 — Ordered byte-keyed maps before records

## Context

The frozen external corpus has 31 supported and 19 unsupported tasks. Its
`GENERALITY_GAPS.json` labels four maps/records blockers, one dictionary and one
nested-collection blocker. These are adapter gaps, not proofs of unexpressibility.
Inspecting the pinned properties distinguishes dynamic keys from fixed fields:

| Candidate | Directly useful blocked tasks | Remaining adapter work |
| --- | --- | --- |
| Records | go_counting (owner + coordinates) | Flood fill, collection serialization |
| Maps | etl, alphametics, forth, camicia | JSON transport, search/interpreter/simulation |
| Neither minimal candidate alone | dot_dsl | Nested graph/attribute maps and parser |

Maps also address repeated names in supported grade_school and sparse/set-like
state in dominoes. Records would group circular_buffer's positional state but
would not supply name lookup, duplicate detection or sorting. No task is counted
as newly supported until its unchanged executable oracle passes.

Pre-implementation o200k measurement of existing grade_school is 409 tokens.
Its duplicate-mask helpers cost 49; offset collection costs 34. An unverified
map-based unique-offset collection prototype costs 70: removing those helpers
would save at most 13 tokens before downstream sorting changes. Maps do not sort;
this is a modest estimate, not a promise to reverse the external Python gap.
The estimate used `tiktoken`'s `o200k_base` on lines 8–9 and line 3 of
`programs/ex_grade_school.nil` and this **unverified** replacement prototype:

```text
(s):v=b(a,@(a,0,!map(),!buffer(0,0);b<#a;a,d(a,b),!has(c,e(a,b))?c:!insert(c,e(a,b),g(a,b)),!has(c,e(a,b))?d:!concat(d,!buffer(1,b));d))
```

Circular_buffer needs its same arithmetic/branches even with records; no measured
record reduction justifies introducing field syntax first. Prior tables remain
frozen as the before measurement. Unsupported tasks have no NIL reference source
from which a defensible token-saving percentage can be estimated.

## Decision

Implement maps first, only in expr-v5, through typed HIR intrinsics and the
existing intrinsic-call grammar. Two homogeneous types: `m` = Bytes -> I64,
`t` = Bytes -> Bytes. This is one map implementation with two result signatures,
not a record system. Arbitrary map-valued entries, heterogeneous values and
records remain postponed. Byte values permit a map containing sequences;
recursive collections still require explicit serialization.

Operations: `map()->m`, `bytemap()->t`; `insert(M,Bytes,V)->M` rejects an
existing key; `put(M,Bytes,V)->M` inserts or replaces; `get(M,Bytes)->V`;
`has(M,Bytes)->Bool`; `size(M)->I64`; `key(M,I64)->Bytes` selects by insertion
index. V is I64 for m and Bytes for t. No deletion, default lookup or field syntax.
Key equality is exact byte equality, including NUL and non-UTF-8. Iteration is
insertion order; replacing a value retains its index. Native hashing is fixed
FNV-1a with collision resolution and full key comparison; hashes never determine
observable order. Reference lookup may use a different indexing implementation.

Maps are immutable semantic values. Aliases retain old contents. Keys and byte
values are owned copies inside a self-contained arena allocation, with no child
GC edges or borrowed slices. get(t,...) and key return fresh owned Bytes; get(m)
and has/size allocate nothing. Existing source evaluation order and lazy arms
remain unchanged.

Use the same 64 MiB live-capacity rule and transient old+result reservation as
sequences. The private payload has 24 metadata bytes, 48 bytes per entry-capacity
slot, twice that many 8-byte hash buckets, and a byte arena. Entry capacity starts
at four and byte capacity at sixteen, doubling as needed. Charge all payload
capacity plus the existing 40-byte allocation header; byte results charge their
own capacity/header. Account identically in both execution paths. These charges
make the maximum depend on key/value lengths and coexistence with other roots.

Argument traps/effects occur first, left to right. Then get missing key is E019,
insert duplicate is E020, key invalid index is E012, followed by any output quota
check E013. Invalid operand/value types (including indexing a map as a sequence) are
existing compile-time E007. Dot field syntax is absent and its invalid character
uses existing parse diagnostic E001; there is no runtime record field trap. Allocation failure is
E013; no host effects are added. Duplicate/missing checks precede allocation even
near the quota. put on an existing key cannot produce E019 or E020.

Reuse requires the existing last-use proof **and** runtime single-root uniqueness.
If either fails, copy the entire owned map. Grow entry/hash capacity geometrically
and rebuild the hash table only on growth. Inserts into a unique map have
amortized constant entry overhead plus key/value bytes, subject to hash collisions.
Integer replacement and equal-length byte replacement can update in place.
Different-length byte replacement repacks owned byte storage and can cost linear
payload work; measure this limitation rather than claiming all map updates O(1).
No reuse changes trap order or semantic result charges. Calls and lazy-region
captures remain conservative whenever their liveness cannot discharge an alias.

## Alternatives

Records first chiefly address one blocked property; they do not cover runtime
names/words or state sets. A generic recursive map would need recursive type and
child-root accounting changes without corpus evidence for their minimal design.
A linear entry list is simpler but makes repeated insertion/lookup quadratic.
User ownership annotations, views and mutable shared maps conflict with scope.

## Consequences

Map construction does not implement a JSON parser or solve the blocked algorithms.
Measure attempted task support and every density loss against frozen contracts;
never add fixture-specific lookup solutions. Test collisions, insertion order,
nested byte values, aliases, calls, loops, lazy traps, quota and growth at O0/O2,
under sanitizers and differential fuzzing. Report insertion scaling, byte-update
repacking costs and performance controls. No syntax compression, dependencies,
default/earlier-profile changes or model trials.

## Estimate correction after implementation

The initial line selection above included grade_school's wrapper and first
mask helper (49 tokens), rather than both duplicate helpers. Rechecking the
committed before source's lines 9–10 gives **79**, not 49, o200k tokens. The
verified rewrite is 367 versus 409, saving 42 tokens (10.3%), instead of the
conservative 13-token estimate. This corrects an analysis indexing error; the
initial decision commit and its forecast remain visible in history. Corpus
oracles and baselines did not change.

## Status

Accepted experimental design before implementation. Implementation and measurements
are pending; this ADR is committed separately before compiler changes.
