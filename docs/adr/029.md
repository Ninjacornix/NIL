# ADR 029 — Validated, statically linked semantic plugins

## Context

ADR 026 permits compiler-visible/static extensions when lifetime, alias, quota,
trap and effect contracts remain visible. An opaque foreign function annotation
cannot prove that C obeys them. Rust forbids unsafe code and the oracle must not
become a second implementation of an undocumented native ABI. This prototype
chooses validated NIL providers, not arbitrary native shared objects. Measure the
cost rather than assume LLVM inlining makes the boundary free.

## Decision

A local `nil-plugin 1` manifest names a numeric plugin ID, a relative NIL provider
file, and exported operation IDs mapped to provider function labels. The common
source form is `!plugin(plugin_id,operation_id,arguments...)`; plugin IDs are
compile-time canonical integers. Existing `!equal` remains a compatibility alias
for the shipped sequence plugin, including the legacy HIR input enum variant.
Execution and implementation leave core; do not migrate another operation.

### Types and versioning

Version 1 is a **semantic linking interface**, not a stable C/binary ABI. Providers
use the same typed HIR as the caller: i64/u64/u128/f64/bool, fixed i64 arrays,
Bytes/Buffer, integer/byte/scalar-record maps and nominal nested records. Record
names resolve against the caller's validated registry; field names/order/types
must match. Unsupported recursive/dynamic collection placements stay unsupported.
Native target layout is compiler-owned SSA aggregates plus private arena handles;
no address is representable in NIL. Reference values use the same type identities.
Unknown manifest versions/types fail E024 before execution. Adding a core type
requires an interface revision or explicit capability support, never guessing a
layout. No promise of loading an old native artifact with a new compiler.

### Ownership and effects

The initial supported declaration is `borrow`: no dynamic allocation, no host
effect, no escape outside returned NIL values. The compiler independently derives
this property from the entire reachable validated HIR; annotations cannot grant
it. Rejected or unknown summaries fail E024. Allocation/host declarations and
opaque native providers are reserved and rejected in version 1, rather than
pretending their ownership contracts are implemented.

Arguments retain caller-owned allocation identities. Provider code cannot mutate
shared storage: replacement/concat/constructors allocate and fail this proof.
Records may be assembled/projected/updated without allocating; returned dynamic
leaves can only alias existing arguments. Caller roots remain live through the
call and returned aliases enter ordinary result roots. The runtime arena alone
owns/frees allocations; all live-capacity and transient charges stay unchanged.
Plugin calls participate in existing interprocedural borrowing/root retention;
they do not acquire a conservative allocation penalty solely for being external.
Unproved sequence reuse stays copying. No provider can obtain a raw pointer.

### Failure, evaluation and determinism

Evaluate arguments once left-to-right before invoking the provider; lazy arms stay
lazy. Signature errors use existing E006/E007. E024 identifies invalid manifests,
exports, version/effect contracts or mismatched record registries. Provider traps
use existing codes and occur at their executed operation, after argument traps;
no remapping or recoverable exception. `equal` preserves matching sequence types,
empty/length-mismatch behavior and binary/integer element equality.

The exported call is one atomic semantic instruction for caller fuel/depth, as
existing intrinsics were. Provider execution has an independent internal safety
budget/depth policy; the shipped finite equality loop must not introduce a new
trap within any allowed 64 MiB input. User-selected caller bounds cannot charge
its hidden element loop. This does not guarantee termination of arbitrary plugin
code; manifests/providers are trusted local code. The prototype must document
its concrete internal policy and test near caller limits.

Reference execution interprets the same independently validated provider HIR;
native execution emits it into the linked LLVM module. Both retain strict numeric
semantics/checks. This avoids an unavailable unsafe Rust dylib loader and keeps
the oracle executable. Golden/adversarial tests supply independence from shared
provider algorithm mistakes. Comparing two lowerings alone is not a semantic proof.

### Trust and loading

Only explicit local manifest/provider paths are loaded at compile time. No remote
loading, package registry, native object/dylib loading or runtime dispatch. Native
code is produced by the existing trusted compiler/Clang toolchain. **There is no
sandbox** for compiled programs or host operations. A trusted provider can consume
CPU, and compiler/runtime bugs remain memory-safety risks; validation is not a
security sandbox. Arbitrary native code would require a separate reviewed ABI
and trust decision; version 1 rejects it.

### Minimal demonstration and ADR 026 verdicts

| Surface | Classification | Implementation |
|---|---|---|
| Generic typed plugin call/linking | Core contract | Validated types, derived borrowing and normal roots/traps |
| Migrated sequence equality | Library/plugin | One algorithm, two typed overloads, old alias preserved |
| Record `bump` operation | Plugin only | Functional count update, nested dynamic fields returned as aliases |

No new Intrinsic variant or second migration. No record equality/formatting or
JSON/grid algorithms enter HIR. Native plugin providers are an explicit deferred
boundary, not an implemented feature.

### Preregistered measurements

Use a 16,777,216-iteration equality hot loop with changing one-byte state so the
comparison cannot be hoisted as invariant. Order the comparison before replacement
to permit the existing single-use reuse proof. Count equal results and verify the
same output before/after. Preserve the starting compiler binary and emitted IR.
Report O0 and O2 medians, sample distributions, time delta divided by calls, and
whether root traffic/reuse stayed removed. The portable element loop may be much
slower than the old memcmp; if material, recommend a future validated native
lowering or keeping the hot algorithm core until such a boundary exists.

Also re-run existing scan16MiB, append1MiB, transform16MiB and map-insert controls
with at least 25 repetitions. Frozen corpus sources/oracles/goldens/baselines remain
unchanged. No density claim or model inference.

## Alternatives

Trusted opaque C annotations recreate the original proof problem and are not
verifiable against bodies. Out-of-process native providers isolate addresses but
copy/serialize values and cannot credibly serve hot loops. Unchecked dylibs add
unsafe loading and an unstable aggregate ABI. Compiler-visible providers are the
smallest sound first boundary, with deliberately narrower capabilities.

## Consequences

Third parties can build and load typed, nonallocating local semantic plugins;
allocation/host providers and stable foreign ABI remain open. Effect visibility
comes from actual code, not trust in a declaration. This prototype can honestly
show a library algorithm losing runtime speed even while its lifetime proofs hold.

## Status

Preregistered before implementation. Stop on any lifetime/alias/quota conflict.
