# ADR 036 — Guarded argument handoff and scalar builders

## Context

Round 16 starts at main 80afb64 / benchmarks 3c29173. The Round 14 origin-set
census reproduces 52 update-return call sites in 18/68 frozen programs. This is
frequency, not ownership. A second conservative analysis over those same HIRs
finds **41 last-use, sequence-typed handoff candidates; 7 additionally prove a
fresh local allocation with no live alias/descendant or duplicated argument**.
Unknown parameter/call/loop origins remain conservative; physical uniqueness
must still be checked at the update, since a callee can create aliases.
`benchmarks/ownership-study/proof_census.rs` records this distinction.

The emitter already drops final-use argument roots immediately before Call and
registers callee parameter roots before any managed allocation. Conservative loop
state roots are dropped before body evaluation; retained roots are the body's
actual input roots. What is missing is admission: Replace outside a proved loop
chain always calls the copying helper, regardless of final use. Concat already
admits guarded final-use updates. A new ownership ABI is unnecessary for this
first implementation and would duplicate the existing root handoff.

## Decision (preregistered before compiler changes)

Retain immutable semantic values, the 64 MiB live-capacity quota and existing HIR.
Admit final-use dynamic replacements in ordinary callees and lazy regions, not
only loop chains. The proof is the conjunction of semantic final use and the
runtime's **exactly one active physical root** check. Final use alone never means
unique. Other live SSA aliases, arguments, caller activations, returned aliases,
loop state and heap child edges retain their roots and force copying. No
user-visible ownership annotation, function variant or indirect ABI is added.
All arguments are evaluated left-to-right before any handoff. Callee roots are
installed before collection can occur; zero-root transfer gaps are safe only
because no managed allocation/collection occurs in them. Return roots are adopted
before the next allocation. Self/mutual recursion use the same protocol, with
bounded call-depth failures unchanged. Terminal failure exits neither expose
partial updates nor permit recovery; earlier host effects remain observable.

For sequence-bearing records and collections, retain existing child-root rules.
Functional record values are copied as typed aggregates. Passing a projected child
while its parent remains live adds a second root and must copy. Do not blindly
release the parent or unrelated fields. Record-buffer last-use replacements may
use their existing guarded helper; scalar read scheduling below excludes records.

### Read-before-write scheduling

Only capture a later i64 element read from the original Buffer/Bytes when its
index is structurally identical (bounded expression comparison, wrapping
constants/add/sub/mul) to the first replacement's index, it is the final original
use, and intervening instructions are allocation/effect/trap-free scalar work.
Reject branches, calls, conversions, divisions, other indexing, aggregates and
allocating instructions in that interval. Do not move source evaluations/ticks.

The first replacement checks its original bounds, byte range and prospective
capacity charge in the original order and with its original diagnostic span;
only then capture the old scalar and perform the guarded update. The later read
uses the captured scalar at its original step boundary. No newly early bounds
trap is possible: that same index was checked by the replacement. Live aliases
still force a copy. If reuse succeeds, old/new identities temporarily share storage,
but no intervening operation may observe quota or allocate; the prospective
first-result charge was checked, and reference live storage agrees again when the
original read dies. If that argument cannot be discharged, do not schedule it.
General record snapshots, arbitrary index arithmetic and effectful scheduling
remain excluded, rather than extending this scalar proof by assumption.

### Singleton builder lowering

Recognize a single-use, adjacent singleton literal or `!bytes(1,x)` /
`!buffer(1,x)` consumed as a concat RHS with a final-use LHS. Keep the existing
surface: **zero token change for existing programs**. A private stack-backed
singleton avoids per-element heap allocation. Its 40-byte header plus 1/8-byte
capacity is still charged at the original construction, rooted during concat and
released at consumption; both construction and concat retain their own spans,
quota checks, byte-range checks and ticks. It cannot escape or survive an intervening
instruction. Heap collection must not traverse/free stack storage. Retain the
copying concat path for aliases and preserve geometric capacity/growth semantics.

Measured cl100k/o200k: `!concat(a,!bytes(1,b))` and buffer form each cost 9 tokens;
`!push(a,b)` costs 5 (saves 4). Do not add push this round: the recognizer speeds
existing programs without expanding core surface. Future source-library spelling
can be considered separately under ADR 035. No intrinsic-count increase.

If hot update callees still pay for malloc/free of shadow-root frames, use
activation-local frame storage: frame links and slots remain identical, unlinked
before returning, with distinct storage per recursive activation. This changes
neither arena ownership nor quota (root-frame storage was never charged). Never
let a frame address escape its activation. Verify under sanitizers before shipping.

### Materialized updates and std sort

Investigate modified sequence access using explicit length-preserving loop chains.
An unchecked store additionally needs physical uniqueness/disjointness for the
whole loop, a proved index range, stable roots and capacity, and preserved quota,
byte-range and trap order. Read-only range proofs alone are insufficient: copied
updates can change the payload pointer. Do not remove checks or annotate noalias
unless these stronger obligations are discharged. A documented non-vectorized
result is acceptable. Earlier profiles remain unchanged.

Once guarded callee updates pass soundness gates, prototype comparator merge sort
in shipped NIL source, using static HOF specialization and ordinary module linking.
Keep core !sort; no migration or reserved std name is implied. Measure source sort
against core and C++ std::sort, and insertion sort against C++ insertion sort.

## Alternatives

Annotations and new ownership types change the language unnecessarily. Blind
last-use mutation is unsound. Inlining is neither an alias proof nor a recursion
solution. Eager old reads change trap order. Removing singleton quota charges
changes E013 boundaries. Runtime reference counting, views and shared mutable
buffers conflict with the established immutable arena model and are out of scope.
A stronger interprocedural ownership specialization can follow if guarded admission
fails the speed target; it must not be assumed sound from candidate frequency.

## Consequences

New adversarial O0/O2 tests/fuzz cover aliases, returned aliases, lazy arms,
recursion, loop state, record children, empty/zero-slot layouts, quota/bounds after
updates, effects and out-of-range scheduled swaps. Compare host effects and
first diagnostic spans where ordering matters. Run all sanitizer suites, three
full-family fuzz seeds, CI both modes, full corpus2815/original610, and every
performance control. Stop on an unexplained divergence or ownership conflict.

## Status

Accepted for this bounded guarded design, superseding the Round 14 draft. Commit
this ADR and the census before any dependent compiler change. Local commits only.
