# ADR 027 — Minimal sized integers and deterministic binary64

## Context

Frozen external Grains needs 2^63, and Armstrong contains 108/127-bit decimal
inputs. Darts needs fractional Cartesian coordinates; Complex Numbers' selected
real-part property accepts real components. Existing types only include signed
64-bit integer scalars. Keep the differential oracle bit-exact and dependencies
absent. This is core type work under ADR 026, not a plugin ABI.

## Decision

Add only unsigned `u64`, unsigned `u128` and IEEE binary64 `f64` to expr-v5.
Existing `i` is signed i64; it and earlier profiles/default retain their meaning.
No i8/i16/i32/u8/u16/u32/f32: byte storage already enforces byte range; no selected
contract justifies extra scalar widths. No new numeric collection/map type.
Signatures use u64/u128/f64. Unsuffixed integers remain i64. Canonical decimal
unsigned literals end u64/u128; decimal floating literals contain a fraction or
exponent, e.g. 1.0, -0.0, 1e-3. Out-of-range/malformed literals fail E001.

Arithmetic requires identical operand types; no implicit mixed-width conversion.
Unsigned +,-,* wrap modulo width, division truncates and traps E009 for zero.
Existing i64 arithmetic is unchanged. Binary64 +,-,*,/ round each operation to
nearest, ties to even, with gradual underflow. Division by zero yields signed
infinity or NaN, never the integer E009 trap. No FMA, fast math, reassociation,
reciprocal approximations, transcendental functions or observable FP environment.
Clang IR/runtime/link invocations explicitly disable contraction and fast math;
emitted arithmetic has no fast-math flags. Verify an adversarial multiply-add at
O0/O2 and inspect invocation/IR rather than trusting defaults.

All NaNs entering via bits/parse or produced by arithmetic canonicalize to positive
quiet bits 0x7ff8000000000000; payload/sign/signaling are not observable. Equality
with NaN is false, inequality true, all ordered comparisons false. Signed zeros
compare equal but remain distinguishable via bits/format and division. Maps still
only accept byte keys; no numeric key equality is introduced. Formatting signed
zeros produces distinct byte keys if those strings are used explicitly.

`bits(f64)->u64` and `floatbits(u64)->f64` expose canonical bit representation.
Conversions i64/u64/u128/f64 are explicit target-named operations. Integer range
failures and nonfinite/out-of-range float-to-integer conversions fail E021 before
any cast; finite fractions truncate toward zero. Integer-to-float rounds ties to
even. Explicit trunci64/truncu64 keep low 64 bits of integer operands (two's
complement for i64); they never accept floats. No implicit truncation/narrowing.

Format extends existing numeric format with decimal unsigned and fixed scientific
binary64: one leading digit, sixteen fractional digits (17 significant), lowercase
e, canonical signed decimal exponent without plus/leading zeros. Signed zero is
preserved; special text is nan/inf/-inf. Fixed precision is larger than shortest
but provides a simple specified round-trip contract. No aesthetics/density tuning.
Reference Rust formatting and C snprintf normalize exponent spelling identically;
only ship after exact special/boundary/random-bit agreement. If they disagree,
stop that operation or implement a proved shared decimal algorithm, not tolerance.

Parseu64/parseu128 accept canonical unsigned decimal (no signs/leading zeros).
Parsef64 accepts complete ASCII decimal grammar (optional sign, digits, optional
fraction, optional e/E signed exponent), plus exactly nan/inf/-inf. No whitespace,
NUL, hex or trailing bytes. Decimal conversion rounds nearest/ties-even; overflow
produces infinity and underflow may produce signed zero/subnormal. Invalid text
fails E022, distinct from unchanged parse-i64 E016. Formatting results allocate
owned bytes under the existing live-capacity quota; parse/conversion/bits allocate
nothing and have no host effect. Arguments/checks retain left-to-right/lazy order.

Native tooling carries u128 in two private little-word i64 slots, f64 in one bit
slot, and u64 in one slot. Values remain typed in HIR and LLVM, not encoded i64
arithmetic. Entry/print conventions are private, not a stable ABI. No new quota,
record, plugin, Unicode or workspace dependency. F64 values store canonical bits
in the reference so Value equality and the fuzz oracle never use approximation.

## Alternatives

Full integer width ladders add unsupported surface; arbitrary precision is not
required by the retained cases. Shortest-round-trip requires a dedicated formatting
implementation/dependency; fixed 17 significant digits meets round-trip first.
Preserving NaN payloads makes platform arithmetic nondeterministic. Fast math/FMA
break bit agreement. Transcendental functions have platform precision variation
and are deliberately absent. Software floats are unnecessary for these four
IEEE basic operations on verified arm64/x86-64 targets.

## Consequences

Four task adapters will be attempted against frozen fixtures/goldens, not declared
supported until evaluator/O0/O2 pass. Armstrong must detect an unsigned accumulation
wrap rather than claim modular arithmetic proves mathematical equality. Existing
cohort/baselines remain untouched. Density may worsen when adding previously
unsupported tasks; report all three cuts without hiding cohort expansion.
Conversion guards precede LLVM float-to-int operations so no poison/UB is formed.
ASan/UBSan, adversarial FMA, special bit patterns, parser/format round trips and
three differential seeds are mandatory gates. No platform-wide correctness claim
from a small random run; unsupported numeric operations remain absent.

## Status

Accepted pre-implementation experiment. No numeric compiler implementation at this
commit; bit-exactness and unchanged-oracle delivery remain unverified gates.
