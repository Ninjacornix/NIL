# ADR-004: MIR and SSA

## Context

Both reports favor compiler-generated SSA, while generated structured control flow avoids bookkeeping tokens. Straight-line M1 needs no separate MIR.

## Decision

Use immutable, single-definition values for the planned straight-line HIR. Consider typed CFG MIR with block arguments at M4, after structured control-flow requirements are known. Document dominance, terminators and side-effect order before implementing it.

## Alternatives

Expose raw SSA to the LLM; impose full CFG HIR now; introduce an empty MIR crate.

## Consequences

No duplicate IR for M1. SSA is an internal candidate, not a commitment to source-level block labels or a finalized control-flow design.

## Status

Proposed; implementation deferred to M4.

## LLVM lowering update

The user-authorized LLVM path generates typed SSA basic blocks and phi joins from
validated structured HIR inside nil-llvm. Portable MIR serialization/canonicalization
is still unimplemented; this backend-specific CFG does not finalize that ABI.
See [ADR 012](012.md).
