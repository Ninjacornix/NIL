# ADR 028 — Immutable records and binding core boundary

## Context

ADR 026 requires a core-or-extension verdict before introducing an operation.
Records are a fundamental product type. The five corpus candidates are
ex_alphametics, ex_dot_dsl, ex_go_counting, ex_camicia and ex_binary_search_tree.
Their frozen contracts need search/parser/game adapters as well as storage. Go
counting's owner plus coordinates and Camicia's two decks are products;
alphametics already has integer maps, dot-dsl additionally needs structured
collections, recursive trees need recursive types. Do not claim five unblocks.

## Decision

Nominal acyclic records precede functions, for example record Pair(left:i,right:s).
Field types refer only to earlier declarations; fields are unique and ordered.
Pair(42,"answer") constructs in declaration order; a.left projects;
a{right:"new"} updates exactly one field. Expressions evaluate left to right,
receiver before replacement value. Original values and dynamic aliases survive.

Records are LLVM SSA aggregates, like fixed arrays, not arena objects. Scalar,
fixed-array and nested-record fields are inline; dynamic fields retain existing
handles. Every dynamic leaf has a shadow root, including repeated aliases.
Reference accounting recursively walks fields and deduplicates allocation IDs.
Inline storage has no capacity and consumes no dynamic quota. Every contained
allocation remains charged at live capacity plus its existing header. Limit
expansion to 128 declarations, 64 fields, 32 nesting levels and 4096 flattened
slots. No recursive types. Construction/projection/update allocate no dynamic
storage. LLVM insertvalue/extractvalue preserve immutable updates without a new
mutation proof. A field extracted while its record is live has an alias root;
existing sequence/map unique proofs cannot silently reuse it. Nonallocating
record operations may borrow; allocating callees/regions remain conservative.

Support records in records and existing sequences/maps as fields. Record map
values initially require only scalar/fixed-array leaves: !map[Pair]() selects
existing packed byte-map storage with a static record value type. Flattened
leaves are 8-byte little-endian slots, u128 low then high: private storage, not an
ABI. Get decodes without allocating; insert/put use existing checked capacity
reservation and unique reuse. Insertion order remains deterministic. Sort mode
0 sorts keys; mode 1 fails E018 (no invented record comparison). Each returns a
typed record. Defer sequence-bearing record map values and record buffers: packed
maps cannot retain dynamic child aliases and Buffer has i64 elements. These need
separate collection/ownership contracts, not a convenience intrinsic.

E023 (Check) means unknown/duplicate record or field, invalid definition or
unsupported aggregate collection placement. E006 handles constructor arity,
E007 field type mismatch. Static errors precede execution. Existing E019 missing
key, E020 duplicate, E018 sort-mode, E013 quota ordering stays unchanged. Record
operations add no runtime traps except existing fuel/depth. Native tooling record
entry marshalling is deferred; use a supported entry wrapper with internal record
calls. Earlier profiles/default and existing program meaning are unchanged.

### Binding ADR 026 verdicts

| Proposed operation | Verdict | Required primitive contract |
|---|---|---|
| Construction | Core HIR | Nominal typed product with visible child lifetimes |
| Projection | Core HIR | Typed borrowed subvalue and transitive alias identity |
| Functional update | Core HIR | Immutable product and explicit operand order |
| Typed record map construction | Core HIR storage | Validated homogeneous packed layout |

Add no intrinsic enum variants: four semantic operations and a typed constructor
overload, no new algorithm. Before: 32 variants plus each lowering (previous
33-operation convention). After: same 32 variants; report record surface and map
overload separately. Reject record equality/order, reflection, serialization,
formatting, default constructors and bulk transforms as future library surface.
Destructuring is postponed lowering to projections, not another opcode.

### Preregistered density expectations

Forecast zero automatic savings on the unchanged 60 supported programs. Grouping
parameters removes repeated signatures but declarations and named projections
add tokens: do not promise net savings without a source rewrite. Attempt Go
counting/Camicia adapters first and report newly supported costs separately from
fixed-task movement. The complex-number real-part task needs no record; do not
rewrite it artificially. Compare any refactor with its old source.

Defer shortest-round-trip f64 formatting: Rust and C printf do not share a
shortest algorithm, and a new shared algorithm without dependencies is not cheap.
Keep ADR 027's exact fixed format; no format migration this round.

## Alternatives

Boxed records require a new transitive arena tracing/update proof. Inline products
preserve existing allocation identities with explicit leaf roots. Generic record
collections expand ownership contracts; opaque libraries cannot define nominal
types and child lifetime relationships.

## Consequences

Bounded products and scalar-record maps have a small, explicit core delta. All
nested dynamic fields must survive allocating calls/regions. Unproved aggregate
loops remain conservative. Generic nested collections and recursive types remain
real boundaries. No ABI, migration or format change is authorized.

## Status

Preregistered before implementation. Acceptance requires differential, sanitizer
and frozen-corpus evidence. Stop at any unproved lifetime boundary.
