# ADR 012 — First LLVM ahead-of-time prototype

## Context

The user requests native LLVM compilation after M2. Structured typed HIR and the
reference evaluator now define arithmetic, branch, loop and resource semantics.
M4 canonical serialization and M10 backend comparisons remain broader future work.

## Decision

Implement one experimental LLVM AOT path now, as explicitly requested. A separate
nil-llvm crate consumes only validated HIR, lowers regions to typed SSA blocks and
phi joins, emits textual LLVM IR, and invokes host Clang to compile/link it.
The internal block builder is a backend lowering stage, not a finalized portable
MIR ABI. Keep the interpreter as the differential oracle. The user subsequently explicitly
requested switching execution to LLVM: `nil run` now builds and executes native
code by default, while `nil build` saves it. Missing Clang is an explicit error;
there is no interpreter fallback.

Generate checked add/sub/mul using LLVM overflow intrinsics. Guard zero division
and MIN/-1 before emitting sdiv. Branch regions remain lazy. Loop-carried values
become typed phi nodes with simultaneous updates. Keep instruction fuel and call
limits in a per-invocation context, with the same charging rules as the evaluator.
No globals are needed for language state; the context is runtime bookkeeping.

A small generated C runtime handles argv, decimal i64 parsing, result/diagnostic
printing and optional in-process timing. Native entry signatures are i64 only,
matching existing source functions. No Rust or NIL interpreter is needed to run
a generated executable. Native builds require host Clang (opaque-pointer LLVM,
15+), system headers/libraries and a linker. Initial hosts: macOS, Linux for CI.
Provide O0 and O2; no custom optimization passes or unsafe Rust/LLVM bindings.

## Alternatives

LLVM library bindings/JIT introduce toolchain/dependency and unsafe-code complexity.
A C transpiler would use LLVM indirectly but would not expose native LLVM IR.
Cranelift/WASM remain candidates for later measured production comparisons.
Implementing a full portable MIR/canonical serializer first is useful later but
unnecessary for this deliberately bounded, user-requested backend experiment.

## Consequences

Native diagnostics preserve codes and spans but report process failure; no recovery
ABI is provided. Build only for the host architecture. Fuel/depth guards can limit
optimization speedups but preserve the current semantics for differential tests.
Never claim performance superiority before measuring in-process execution.
Full M4/M10 completion, packaging LLVM, cross-compilation, production sandboxing,
plugins and custom optimizations remain outside this prototype.

## Status

Accepted for the requested LLVM prototype; production backend choice remains open.
