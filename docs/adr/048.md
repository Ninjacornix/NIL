# ADR 048 — Simultaneous contiguous functional update chains

## Context

Maintainer decision, 2026-10-09: expr-v5 evaluates contiguous update-chain
operands before committing their writes, as loop-state transitions already do.
This gives natural immutable-value swaps a read-before-write order without
requiring authors to know the native ownership optimizer. ADR 046/047 make
allocation/stack exhaustion ordinary environment failures. Other diagnostics,
laziness, host effects and aliases remain defined.

## Decision

For `a[i:x][j:y]...`, evaluate the receiver, then every index and replacement
value left-to-right, using the lexical original values, before performing any
write. Commit replacements in source order; duplicate targets use the last
replacement. Each committed replacement performs its original bounds and
byte-range validation at its original suffix span. Operand effects and traps
occur before write checks; a failed operand prevents all writes. A failed write
prevents subsequent writes. This is an explicit diagnostic/effect-order change
for expr-v5, not a claim that faulting programs retain the old ordering.

Apply the same rule to contiguous record-field functional updates. Immutable
alias semantics, layouts and runtime uniqueness checks remain unchanged. Other
profiles use their existing eager lowering. There is no new intrinsic or grammar
spelling; the enum stays at 35 variants.

Parentheses alone do not break a chain. An explicit local binding, a read suffix
(index or field projection), a call or control-flow result forms an evaluation
boundary. A chain inside an operand completes as that operand; operands in lazy
arms remain selected-arm-only. Explicit bindings still evaluate exactly once at
their binding point. No write crosses a binding, a host effect or a lazy-region
boundary beyond the order explicitly specified for its own contiguous chain.

Lower this general surface rule to ordinary first-order SSA: operand instructions
precede the Replace/UpdateField instructions. HIR validation, reference execution
and native lowering therefore see the same order. Liveness and runtime alias
checks decide reuse after lowering; a live alias must still force copying.
No index-shape matcher, speculative trap suppression or renamed operations.

## Alternatives

A new swap operator would shorten selected source but would leave natural update
chains expensive; source std swap already exists. More speculative replay would
require guards for operations whose source order is now explicitly simultaneous.
Leaving grouped chains eager would make parentheses change effect/trap order and
is rejected. Reordering across explicit binding/control boundaries is rejected.

## Preregistered forecasts (before implementation)

Measured cl100k/o200k: `a[b:a[c]][c:a[b]]` is 9/9 tokens before and after:
**zero token change**. `!swap(a,b,c)` is 6/6; `!pop(a)` is 4/4 versus
`!slice(a,0,#a-1)` at 10/10. This step changes no frozen source file.

Round 23 B2 already reduced natural heap copy traffic to about 0.8 MB/23 events,
so do not forecast another large byte reduction there. Forecast natural heap
35–60 ms versus the Part A 64.268 ms median, with tuned performance within noise. Natural
qualification forecast **19–20/150**, tuned **22/150**. The other cross-region
cliffs are forecast unchanged: balanced tree ~1.496 s, course ~4.257 s, BST ~1.414 s,
spiral ~28.873 ms. Natural physical copy payload forecast 399–400 GB; the 80 GB BST
path-correlation limit is outside this rule. Forecasts are not targets to satisfy
by editing natural sources.

## Variant matrix and admission

Test Buffer, Bytes, fixed arrays and record fields; reordered writes, extra
bindings, grouped versus ungrouped chains, helper operands, repeated indices,
nested chains, every operand position trapping or performing host effects,
selected/unselected lazy arms, loop state, returned/local aliases and record
children. Assert exact code and span for non-resource failures at O0/O2.
Explicitly test that an old alias retains its original payload. Preserve earlier
profile goldens. Every discovered bug gets a regression.

Full CI debug/release, sanitizers, two full differential seeds with joint
resource escalation, frozen corpus 2,815/original 610, both natural/tuned cohorts,
isolated >=15-repeat cliff timings and >=25-repeat controls must pass before
std inlining begins. Report non-resource divergences as failures, never resource
inconclusives. Do not attempt any held-out problem.

## Consequences

Successful immutable results remain the same. Fault/effect order in contiguous
expr-v5 chains changes deliberately: all operand work precedes replacement
validation and writes. This does not fix parent/caller roots or correlated
sequence-valued lazy-arm retention; those remain general-analysis gaps.

Accepted for Round 24 Part B after Part A admission. Commit before compiler
