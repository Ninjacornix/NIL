# ADR 022 — Corpus-driven sequence operations

## Context

The verified 24-task corpus costs 36.7–43.5% more source tokens than Python.
Delimiter scans, repeated field conversion, buffer counting/construction and
manual byte equality are measured costs. Shortening identifiers or grammar would
not express the missing work. [Pre-implementation ranking](../experiments/V5_GENERALITY_IMPACT.md)
was committed as `5832936` before compiler changes; prototypes were token-counted
but explicitly unverified.

## Decision

Add three syntax-independent typed HIR intrinsics using existing v5 syntax:
`parsebuf(Bytes,Bytes)->Buffer`, `find(S,I64,I64)->I64`, and
`equal(S,S)->Bool` where S is Buffer or Bytes and operands have matching types.
Keep earlier profiles/default, grammar and Rust workspace dependencies unchanged.
No environment operation, nested sequences, records or multi-result syntax yet.

Parsebuf uses an explicit byte separator set, permits empty input and one terminal
separator, rejects empty fields and shares parse's canonical decimal conversion.
Count, reserve exact-capacity output under the existing 64 MiB policy, then convert
fields in order: E013 precedes E016. Its byte operands remain rooted across result
allocation. It cannot reuse a different-width byte input; its fresh Buffer result
uses ordinary existing concat/replacement ownership proofs. No views are returned.

Find checks start in [0,length] (E012), then byte needle in 0..255 (E014); absent
returns length. Equal compares values, never identities. Both are allocation-free,
with no host effects; extend the HIR greatest-fixed-point borrowing whitelist.
This property is not a purity/nontrapping LLVM promise. Preserve argument, lazy
branch and effect ordering. New helpers receive the existing diagnostic spans.

The native C runtime implements checked operations; LLVM emits typed calls, with
LTO permitted to inline normally. Reference conversion uses the same canonical
rules independently. No new unchecked memory access or user ownership syntax.

## Alternatives

Push-only builders leave scans and parsing scaffolding; text append already reuses
storage. Parsebuf removes that numeric scaffolding more directly across six tasks.
Multi-result bindings/records and nested-line split would add types/grammar/lifetime
rules for less demonstrated impact. Find exposes boundaries with existing scalar
state. Task-specific min/max/sum/dot intrinsics would conceal algorithms and inflate
the core instruction set; reductions remain programs. Regex/Unicode and environment
Host contracts remain separate work. Keep old representations as regressions.

## Consequences

Three provisional application operations, no new types. Scalar searches and
comparison can borrow across calls/loops. Bulk conversion performs two scans and
allocates once; it does not remove slice allocations in general line processing.
Correctness evidence must cover signature failures, canonical/bounds/range/quota
priority, allocation lifetimes, immutable aliases and lazy effects at O0/O2.
Re-measure unchanged corpus oracles and performance controls; estimates are not
results or evidence of model efficiency. Every density loss remains published.

## Status

Accepted for the experimental expr-v5 profile. Final verification and measurements
are recorded in the goal's validation/benchmark reports; no default selection.
