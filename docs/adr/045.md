# ADR 045 — Logical quota versions and memory-model admission

## Context

Round 23 starts at main `7c48c4a`, benchmarks `ec505b3`, on local branches
`feat/core-memory` / `exp/core-memory`. Nothing is pushed. Frozen natural sources
and the 114 held-out problems are not edited. Round 22 reports natural 19/150,
tuned 22/150; natural REQUIRED payload is 1,581,298,251,755 B and AVOIDABLE
payload 160,056,657,866 B. The largest cliff is a 24,962.076 ms natural heap
against 11.439 ms C++. These are previous measurements, not new results.

The evaluator admits operations against distinct live storage identities plus
the result's transient capacity. The native runtime counts physical owning
allocations. One in-place result can preserve the next reservation; several
simultaneously live versions cannot share without additional logical charges.
ADR 044 therefore keeps copying across allocation and second-update barriers.

There is also a starting-point admission risk, found by source inspection before
implementation: `FileHost::read` returns a whole-read error before the evaluator
charges its result, whereas `nil_read` checks an oversized successful prefix
before a subsequent I/O error. A controlled partial-read failure must be audited
before claiming every reference/native E013 boundary already agrees.

## Decision

### Admission and sequencing

Accept the **experiment and proof obligations**, not an unimplemented ledger as
proven. B1 must first establish compatible baseline observations, including failed
host reads, and then preserve them. If preserving both paths contradicts exact
reference/native agreement, stop at B1 and publish the counterexample. Do not
silently choose an error priority. B2–B4 may proceed only after B1 passes every
gate. G1 remains excluded: this decision does not supply its missing provenance.

### Logical ledger contract

Charge a logical owning version once while reachable through HIR execution roots;
aliases of that version share its identity. A functional allocation/update
reserves its full result capacity before producing it, even if physical reuse is
possible. Dead versions cease to be charged at the same instruction boundaries
as the starting evaluator. This is an execution-liveness rule, not "payload is
never read again": a live parent's unused child still retains its charge.

An implementation needs version identities distinct from payload addresses and
separate physical reachability. Its events must be emitted from validated HIR,
including parameter/result alias propagation and selected region execution.
Sharing cannot merge charge identities. A version represented only by cached
reads still retains its logical charge until its semantic death. Old and new
capacities remain separate through growth/realloc. A transient reservation has
the operation's original span and is released at the original boundary.

Records have no independent flat-value charge; their reachable dynamic fields do.
Record buffers charge `40 + (capacity + 1) * max(slots, 1) * 8` and retain child
version identities once per reachable owning version. Maps retain their existing
capacity/layout and owned key/value accounting. Child identity deduplication must
match the evaluator, including shared children. Stack singleton temporaries retain
their ordinary `40 + width` charge despite owning no heap allocation.

ADR 038 reconciliation commits logical slot/mirror deltas before every quota
observation; physical reclamation is separate. ADR 039 recycled slots change
which version they retain, not that version's identity. Replay cannot delete a
logical root merely because its physical reads were cached. Collection discards
unreachable payloads without releasing still-live logical charge tokens; growth
relocates physical references without renaming logical versions. No additional
physical payload copying or retained payload is licensed by the ledger.

B1 changes no language quota rule, limit, diagnostic or optimization admission.
Its old/new trace must agree on each reservation, live version, code and span.
Allocator exhaustion is not a deterministic quota oracle and must be reported
separately if encountered; it must not be presented as successful quota parity.

### Conditional G2 admission

After B1, remove a barrier only when cached reads have proved nontrapping guards,
all distinct version charges/deaths remain represented, and original effects and
checks still execute in order. A second replacement keeps both original and
intermediate logical charges even when they share payload. Allocations remain at
their source positions and can still fail there. Unknown dependencies, escaping
aliases, record-child provenance and effects keep ordinary copying; no narrower
expression recognizer substitutes for the general SSA proof. Bounded replay must
also preserve E008 instruction/call accounting or retain ordinary execution.

### Conditional source std swap/pop

Reserve `!swap(sequence,i,j)` and `!pop(sequence)` only if their later ADR 035
admission succeeds. Prefer compiler-versioned NIL source and ordinary body-derived
proofs, with zero new intrinsic variants. Pop returns the shortened sequence,
**not** a removed element; the latter remains ordinary indexing. Initially Buffer
and Bytes; record buffers only if the same layout/child proof applies unchanged.

Swap has the observable order of `a[i:a[j]][j:a[i]]`, including left-to-right
argument evaluation, both original reads, checked updates and transient capacity
reservations. Reads/checks precede writes only when the existing error/effect order
is preserved. All checks must precede any externally observable mutation. An alias
forces copying. Pop has `!slice(a,0,#a-1)` semantics: empty input E012, result
capacity length-minus-one, prospective reservation before mutation. No new error
code or recovery semantics. Std source diagnostics must have documented provenance;
do not claim caller spans without demonstrating their mapping.

Measured with tiktoken 0.12.0 before implementation (same in cl100k/o200k):

| Candidate | Tokens | Equivalent | Tokens |
|---|---:|---|---:|
| `!swap(a,b,c)` | 6 | `a[b:a[c]][c:a[b]]` | 9 |
| `!pop(a)` | 4 | `!slice(a,0,#a-1)` | 10 |
| `!remove_last(a)` | 5 | same slice | 10 |

Choose swap/pop, conditional on semantics and speed; spelling alone is insufficient.
Frozen natural sources do not acquire these calls and cannot claim their savings.

### Conditional limits and stack safety

Re-register ADR 043's proposed v5 defaults: 256 MiB, depth 1024; its measured worst
admitted reservation is 52.0 MiB, so memory headroom rises without a qualification
claim. Keep explicit 64 MiB / 256 in existing tests and fuzz. Earlier/default
profiles keep their meaning. Rust evaluator/native options carry both limits;
CLI `--memory-limit BYTES|NMiB` and `--call-depth N` configure execution/building.
Changing defaults is an explicit B4 semantic change, never part of B1 zero-change.
Reserve-as-if-copying remains. Invalid options use E010, exhaustion E013/E008;
ADR 043's erroneous E010 call-depth label is not adopted.

Reference frames remain heap-allocated. Native bounded and unbounded calls need
both configured-depth checks and an independently safe stack-headroom mechanism.
Checking after a large callee prologue is insufficient: guards must run before
potentially overflowing frame allocation, including recursion/mutual recursion.
No clean-E008 claim without large-frame and deep-recursion O0/O2 evidence. If this
cannot be proven, B4 does not ship; it is not hidden by raising a limit.

## Alternatives

Raise quota or drop reserve-as-if-copying: a different semantic decision, rejected
for B1. Charge physical bytes only: cannot admit G2 sharing without changing E013.
An accumulated allocation counter: rejects dead-data loops, already rejected.
Infer logical death from payload-read absence: breaks parent-retention witness.
New swap/pop intrinsics: unjustified before ordinary source/std proofs are tested.
Conflate a host read error with quota: chooses the very ordering being audited.

## Consequences

This ledger requires alias and lifetime metadata, not a renamed physical counter.
The two Round 22 quota witnesses must keep their exact failures. A baseline host
contract contradiction needs a separate maintainer-approved semantic decision;
this ADR does not authorize repairing it or proceeding through it.

## Status

Accepted preregistration and conditional admission contract before any Round 23
code. Implementation admission is pending; no ledger, G2 lift, std operation or
limit change is claimed by this document.
