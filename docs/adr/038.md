# ADR 038 — Deferred root reconciliation and source-std push

## Context

Round 16 (ADR 036) brought append to C++ parity, but conditional builders stayed far
off: overseer re-measurement put std filter at 274.7 ms and a hand-written filter at
537.2 ms against C++ `std::copy_if` at 31.9 ms (16 MiB). This round is implemented by
the overseer because the implementing agent hit its usage limit; there is no
independent audit, and every gate is self-run.

### Diagnosis (measured before any implementation; experiments reverted)

1. **The Round 16 "shape-sensitivity" finding was wrong.** Both filters emit the same
   singleton fast path (`nil_make_temporary` + `nil_concat_unique`). With a predicate
   that LLVM cannot specialise (`a<128`, also keeping 50%), inline-once, helper and
   inline-twice forms all run 535-538 ms. The 274.7 ms std result came from the
   benchmark's even-byte predicate in helper form, a fragile LLVM optimisation that
   disappeared under an unrelated runtime change (273 -> 523 ms). The true cost of the
   conditional-builder path is ~530 ms (~17x C++) for every shape.
2. **Root bookkeeping is ~85% of that cost.** The hot loop performs about 12 shadow-stack
   root updates per element (14 on kept elements). Each update runs `nil_drop` and
   `nil_retain`: a read-modify-write of the old and new objects' root counts and, on
   0<->1 transitions, an update of the live-capacity total. An unsafe experiment that
   reduced `nil_root_store` to a plain store cut the filter from ~530 ms to ~70 ms
   (2.2x C++) with byte-identical output.
3. A one-element `memcpy` in `nil_concat_unique` costs ~24% on the `a<128` filter
   (537 -> 409 ms), but the gain is layout-sensitive and not pursued separately.

## Decision

### Deferred root reconciliation

A root slot write becomes a plain pointer store. Each frame doubles its slot array:
`slots[0..n)` hold the values the emitted code intends to root, and `slots[n..2n)` hold
the **committed** values whose root counts have been applied. Root counts and the live
total are reconciled (drop each committed value that differs from its slot, retain the
new one, then record it as committed) only at **observation points**: every runtime
operation that reads a root count or the live total, may collect, or may allocate.

- `nil_roots_enter` reconciles the current top frame before pushing a new one, and
  `nil_roots_leave` drops the frame's committed values. Only the top frame can therefore
  hold unreconciled slots, so reconciliation is bounded by one function's slot count,
  never by stack depth.
- Root counts and the live total are sums over slots. Reconciling the final slot values
  yields exactly the counts the eager scheme reaches after the same sequence of stores,
  whatever intermediate values the slots held. Every observation point reconciles before
  reading, so every observation sees the eager value: identical copy-vs-reuse decisions,
  identical E013 boundaries, identical collection behaviour. Between observation points
  nothing reads counts.
- Growth relocation (`realloc` in unique concat paths) writes the relocated pointer to
  both the slot and its committed mirror, keeping them equal.
- Values held only in registers are unaffected: the emitter's rooting obligations are
  unchanged. Only the moment counts are applied moves.

Rejected alternatives: computing roots by scanning all frames at safepoints (cost grows
with stack depth and with record child graphs); emitter-level elimination of redundant
re-rooting (a larger, riskier refactor; still possible later on top of this).

### Source-std `!push`

`!push(b,x)` costs 5 tokens on cl100k/o200k against 9 for `!concat(b,!buffer(1,x))` or
`!concat(b,!bytes(1,x))`. Add it to the source std as one line per sequence type, not as
an intrinsic (count stays 35). The std overload is selected by the first sequence-typed
argument.

| newline scan 16 MiB | 10.5 ms | unchanged (+-5%) | — |
| `!push` builder vs concat form | — | within +-10% | — |

The Round 17 target (filter within 2x of C++) is **forecast to be missed**: the forecast
range is 3.8-6.9x. The remaining cost is per-kept-element reconciliation plus temporary
handling. No corpus output changes; no new diagnostics; no gate regressions.

## Consequences

Root counts are no longer exact between observation points; any future runtime code that
reads `roots` or the live total must reconcile first. This rule is documented at the
reconciliation function and enforced by tests that toggle slots between observations.

## Status

Accepted before implementation. Implemented and self-audited by the overseer.
