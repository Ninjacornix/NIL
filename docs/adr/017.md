# ADR 017: Runtime sequences and explicit application effects

## Context

Fixed arrays cannot represent runtime-sized files or collections. The maintainer
selected application programs with runtime-sized data, files and text rather than
drivers. Existing immutable values and native/reference parity should be preserved.
Memory ownership, host effects and an external ABI were previously unresolved.

## Decision

Add opt-in expr-v5 with immutable i64 buffers and byte sequences. Text literals
encode UTF-8; sequence indexing remains byte-based. Typed intrinsic operations
construct, slice, concatenate, format/parse, and perform explicit file/stdout I/O.
Keep these semantic operations independent of source spelling in HIR.

Use an execution-owned native arena with a cumulative 64 MiB charge (payload plus
32 bytes per allocation), reclaimed after result consumption. The reference path
uses shared immutable values and matching charges. Bounds/byte/allocation failures
are explicit. Copying is the initial lowering; views/reuse need subsequent proofs.

Reference execution denies host I/O unless a Host is supplied. Native application
executables use normal OS permissions; there is no sandbox claim. External calls
carry observable effects and cannot be treated as pure. File failures trap for now.

## Alternatives

Raising the fixed-array cap does not solve runtime lengths. Raw pointers introduce
layout, aliasing and lifetime decisions before applications require them. Mutable
shared buffers would change current alias/loop semantics. An interpreter-only
extension would abandon the established native pipeline.

## Consequences

Programs can process arbitrary-sized inputs within the configured prototype quota,
copy binary files, manipulate text, and pass sequences through functions and regions.
Earlier profiles retain their semantics. New native entry text/list encodings are
private tooling; no C ABI is established. Copy-heavy loops remain costly. Unicode
character operations, recoverable errors, richer capability policies, records,
widths/floats and integration ABI remain separate decisions.

## Status

Accepted implementation experiment under the application-program target.
64 MiB, trapping I/O errors, intrinsic names and entry encodings are provisional;
none is evidence of an optimal model-facing representation.
