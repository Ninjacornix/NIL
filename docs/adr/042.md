# ADR 042 — Scalar operators, constants and immutable local bindings

## Context

Round 20 starts at main `851223b` / benchmarks `6fd268d`. The maintainer
requires core operators and constants. The fixed NeetCode sample additionally
shows an update-scheduling cliff: repeated child selection and original-buffer
reads keep aliases live during heap swaps. A binding must evaluate once at its
source position; it must not license speculative reads or mutation of aliases.

The Round 19 full-source density figure includes a large repeated Python input
adapter. It is not a reliable algorithm-density comparison. This round reports
full source, algorithm kernels, and independently verified minimal-I/O copies.
Frozen contracts, fixtures, goldens and Python/C++ reference sources stay intact.

## Decision

### Scope and placement

Extend only expr-v5. Earlier profiles/default and previously valid v5 programs
retain their meaning. Add syntax-independent BinaryOp/UnaryOp scalar semantics;
no new Intrinsic variants (35 before/after). Under ADR 035 scalar/bit primitives
belong in core. Abs/min/max have scalar range/NaN/zero contracts and evaluate
operands once; use core scalar operations rather than an unproved source wrapper.
Sqrt/floor/ceil/trunc/round likewise are IEEE scalar primitives. Constants and
bindings are frontend lowering only; neither is a runtime intrinsic/library.
No transcendental math, mutable locals, closures, new ownership syntax or types.

A binding prefix is `name=initializer; continuation`. Multiple prefixes evaluate
left-to-right. Parentheses delimit a single-expression scope. At the start of a
loop/each result list, prefixes scope over the entire list, so a computed child
can be used by both the replacement and next loop-state index without a tuple type.
Names use lowercase/underscore ASCII identifiers with optional digits; built-in
literal names/true/false/loop are reserved. Value names and positional function
call labels have separate resolution; `b(...)` remains a positional call.

Bindings resolve directly to AST value IDs and then typed SSA IDs. No copy, tick,
root slot, common-subexpression elimination or evaluation rescheduling is added.
The initializer sees the previous binding (if shadowing); subsequent references
see the new value. Scope exit restores the old binding. Lazy arms inherit outer
bindings and evaluate only if selected. As today, loop/each state regions are
closed lexical scopes: outer values must be passed in initial state; no implicit
captures are introduced. Bindings inside a state region may shadow its positional
values and do not leak into another region or iteration. Function values retain
the existing specialization restrictions; no indirect call is introduced.

### Operators and failure ordering

Arithmetic and bit operators evaluate left then right, once, before their own
check. `%` truncates the quotient toward zero; remainder follows the dividend's
sign. Zero divisor is E009 with division's diagnostic text and operator span.
`i64min % -1` is 0 without executing a poisonous native remainder instruction.
Unsigned remainder is ordinary u64/u128 remainder. No floating remainder.

Bit operations accept equal-width i64/u64/u128; complement preserves width.
Left shift wraps at the value width; i64 right shift is arithmetic and unsigned
right shift is logical. Shift counts are i64, checked 0..width-1; invalid counts
raise E021 (numeric range error) before the LLVM shift, with the existing range
error text. No masked counts, implicit mixed-width arithmetic or undefined shifts.

Precedence high-to-low: postfix/prefix, `* / %`, `+ -`, `<< >>`, comparisons,
`&`, `^`, `|`, `&&`, `||`, ternary. Existing comparisons retain their common
precedence/left association; do not silently adopt a new equality grouping.
`&&`/`||` accept bool and lower to existing lazy If regions. `!` is bool negation
unless it introduces an existing reserved operation, std call or qualified module
call. Use `!(b(x))` when negating a call that resembles a reserved operation name.
Unselected expressions must have no effects, allocation, ticks or traps.

Abs accepts every numeric type: unsigned identity; i64min raises E009 signed
overflow; f64 clears the sign and canonicalizes NaN. Min/max accept equal numeric
types. f64 propagates canonical NaN from either operand; min of signed zeros is
-0 and max is +0 regardless of operand order. Integer min/max compare normally.

### Deterministic floating operations

Sqrt, floor, ceil, trunc and ties-even round accept/return f64 only. Preserve
signed zero and infinities; canonicalize all NaN results. Negative sqrt yields
canonical NaN; sqrt(-0) preserves -0. Finite rounding yields the exact prescribed
integral f64, preserving the input sign when the result is zero. No FP exception
flags or errno are observable. Round-to-nearest ties-even is the execution model;
no fast-math, reassociation, reciprocal approximation or FP contraction.

Use Rust's specified f64 operations in the reference and matching LLVM scalar
intrinsics, with explicit canonicalization. Verify special-value and random bit
patterns at O0/O2, including halfway values and subnormals, not approximate
comparisons. LLVM's [roundeven contract](https://llvm.org/docs/LangRef.html#llvm-roundeven-intrinsic)
and Rust's [sqrt precision](https://doc.rust-lang.org/std/primitive.f64.html#method.sqrt)
provide the relevant definitions. If parity cannot be established, exclude that
operation and report the limit rather than weakening the oracle.

### Constants and literal grammar

Reserve bare `i64min/i64max`, `u64min/u64max`, `u128min/u128max`, `inf/nan`;
`-inf` is the negative infinity literal. These lower to existing typed constants.
Inf/nan are beyond the maximum positional parameter label (4096 parameters), so
no previously valid bare reference is repurposed; calls retain their namespace.
NaN is 0x7ff8000000000000. Keep existing 17-digit formatting unchanged.

Hex/binary use lowercase `0x`/`0b` prefixes and canonical lowercase digits,
no leading zeros except zero itself. Unsuffixed magnitudes fit positive i64;
negative magnitudes may reach i64min. u64/u128 suffixes select unsigned type and
check its range. No negative unsigned literal. Existing exponent literals remain
f64; exact-integer exponent alternatives did not save measured tokens.

### Diagnostics, proof preservation and validation

E001 syntax/literal/span; E005 unbound value; E006 call arity; E007 operand/type;
E009 zero remainder/abs overflow; E021 shift range. No new diagnostic space.
Unary scalar operations participate in SSA liveness and allocation-free borrowing.
Keep all root/descendant, quota, alias, host-effect and trap-order obligations;
binding an alias does not make storage unique. Restrict snapshot equivalence to
its existing nontrapping Add/Sub/Mul whitelist when the binary enum grows.

Tests/fuzz include every width/boundary, all shift edges, mixed-type rejection,
short-circuit effects/traps, local scope/shadowing, each/loop/lazy arms, original
aliases and E013 boundaries. Inspect IR both for admitted reuse and live-alias
copy fallback. Existing profile and application corpus goldens must stay unchanged.

## Forecasts and frozen measurement protocol

The five cliff sources are rewritten with ordinary named values; no manual
instruction movement, hidden unchecked operation or altered algorithm. Last Stone
Weight child-index binding should remove repeated calls and allow the existing
snapshot proof. Other samples bind old scalar/node/field values before updates.
Forecast medians: heap 15–100 ms (may miss 3×), balanced tree/BST 15–60 ms,
course schedule 15–100 ms, spiral 15–100 ms. These are preregistered hypotheses,
not proof that a binding alone removes callee-held aliases. Publish misses.

Preserve the 29-source admitted cohort for paired before/after. Rewrite samples
where operators/constants/bindings simplify the actual algorithm; record per-source
token deltas. No new tasks or reference/oracle/golden edits. Reverify all admitted
sources reference/O0/O2 and measure >=15 serial rotating whole-process repeats,
min/median/max against the same original C++ algorithm. Update status counts,
retaining seven blocked and 114 unattempted unless newly validated explicitly.
Historical append/scan/transform controls use their existing inputs/methodology;
retain raw data outside git and repeat any apparent non-noise regression.

Density: (1) complete frozen-style programs, (2) algorithm-only typed kernels
with file decoding/encoding excluded for every language, (3) new minimal-I/O
copies written only for measurement. Preserve original Python/C++ sources and
all fixtures. Kernel extraction boundaries and adapter exclusions must be explicit
per task; kernels/minimal copies must execute against unchanged oracles. Keep the
same algorithms; do not compare a hand-rolled NIL algorithm to intentionally
verbose Python. Count all language-specific kernel helpers. Report bytes/characters
and both tokenizers, per problem/aggregate, lead with the least favourable cut.
No TCR/generation inference. Forecast: removing the repeated Python reader will
reverse Round 19's -19% headline; expect NIL kernels to cost 20–100% more than
Python. Measure rather than asserting any point estimate.

## Alternatives

Mutable locals undermine immutable proofs. Automatic capture of every outer local
in loop state prolongs roots/quota lifetimes unnecessarily. Runtime binding opcodes
or broad read hoisting add proof surface without need. Masked shifts hide mistakes;
float transcendental libm calls lack cross-path bit-exact contracts. Source min/max
wrappers duplicate operands and do not establish NaN/zero semantics. A new profile
is unnecessary because selected spellings repurpose no valid old syntax.

## Consequences

Scalar semantics grow; intrinsic enum count stays 35. Operators do not automatically
fix poor algorithms or make every update uniquely owned. Current default and prior
profiles stay unchanged. Core primitives are maintainer-required even where a token
forecast is neutral or negative. Local binding speed and corrected density remain
empirical results. Nothing is pushed.

## Status

Accepted preregistration. Commit before compiler changes and sample rewrites.
