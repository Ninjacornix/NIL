# ADR-002: Initial execution backend

## Context

design.md proposes MLIR/LLVM or early direct LLVM; report.md explicitly says to build a HIR interpreter before lowering. The current task prioritizes deterministic tests and rapid iteration.

## Decision

Plan a reference HIR evaluator for M1. Keep it as an oracle after codegen exists. Defer MIR implementation and production native backend selection. No backend code is implemented in the setup pass.

## Alternatives

| Candidate | Evaluation for NIL |
|---|---|
| Reference interpreter | Smallest semantic experiment, no external codegen toolchain; runtime is not representative of native execution. |
| Cranelift | Designed for fast compilation and used for JIT/AOT; promising later development backend, but adds codegen/ABI integration now. |
| LLVM | Reusable target-independent machine-code generation; strong candidate for production, but premature integration for six core operations. |
| WebAssembly | Portable target requiring emission plus an execution host; useful later, not itself a complete frontend/backend implementation. |
| MLIR → LLVM | Research-preferred extensible lowering candidate; assess its integration cost when plugins and MIR requirements are concrete. |

Primary references checked for this comparison: [Cranelift](https://cranelift.dev/),
[LLVM code generator](https://llvm.org/docs/CodeGenerator.html),
[WebAssembly goals](https://webassembly.org/docs/high-level-goals/).
Relative integration effort is an engineering judgment, not a measured performance result.

## Consequences

No native speed or binary-size claims in M1. M10 compares bounded prototypes using NIL workloads before choosing a production backend.

## Status

Accepted for M1; production backend unresolved.

## M1 implementation update

The user subsequently authorized M1 implementation. The reference interpreter,
line parser, typed HIR and diagnostic contract are now implemented and tested.
These are M1 policies; final syntax, production backend and expanded types remain
unresolved. The earlier setup-only delivery constraint no longer blocks M1.
