# ADR-008: Canonicalization

## Context

Both reports seek one representation per operation but allow different experimental profiles. Full semantic equivalence is not tractable as a routine compiler normalization.

## Decision

Use exactly one spelling per operation within lines-v0. Plan deterministic name resolution and HIR IDs in M1. At M4 specify versioned serialization and structural canonicalization with idempotence and round-trip tests.

## Alternatives

Aliases within one profile; freeze a binary ABI before evidence; normalize all equivalent algorithms.

## Consequences

Whitespace flexibility is not semantic aliasing. Operand reordering must account for traps/effects. Never conflate canonical bytes with token-efficient generation.

## Status

Accepted principle; algorithm/format deferred.
