# ADR 014 — M3 typed values and fixed-array experiment

## Context

The integer/control-flow core is executable and tested. M3 requires new types to
answer concrete programs, without widening the core speculatively. Array sum,
dot product, maximum, binary search and transforms need aggregate storage; bool
function boundaries need explicit signatures. Driver pointers/floats are separate
requirements without current acceptance programs. Expr-v3 semantics must remain
available unchanged.

## Decision

Implement opt-in expr-v4 as a v3 extension with explicitly typed bool/array
parameters/results and immutable fixed-size i64 arrays (0..256). Length is a type;
reads/replacements have mandatory bounds traps. Reference evaluation and LLVM
operate on the same semantic HIR. Typed native entry uses a flat slot bridge rather
than assuming C and LLVM aggregate ABIs coincide. Keep legacy all-i64 driver/ABI.

A local screen of equivalent signature snippets under pinned cl100k/Qwen measured
numeric lengths 23/23 tokens, tagged a8 lengths 24/24, bracket lengths 26/26 and
full [i64;8] annotations 39/44. Numeric array lengths inside parenthesized typed
headers are the provisional surface choice; the context makes parsing deterministic.
Full-program benchmarks are required. This is not evidence about LLM success/TCR.

## Alternatives

Pointers/slices require ownership/lifetime/aliasing/effect contracts before safe
optimization. Mutable language-level arrays complicate HIR effects; immutable values
can represent local updates without visible alias changes. Dynamic arrays require
allocation/failure semantics. Extra widths/floats need conversions and rounding
policies. Named structs remain useful later, but homogeneous arrays already answer
the selected corpus. Freezing expr-v3 would change existing arithmetic programs;
a new opt-in profile preserves compatibility.

## Consequences

Arrays can traverse calls, branches and loop state with strong validation; compiler
backends may eliminate copies only while preserving value semantics and traps.
Finite length bounds restrict this milestone, not long-term aggregate capacity.
CLI slots are tooling encoding, not source inference. Rust API consumers must handle
new Type/Operation variants; evaluator Value is Clone rather than Copy to support
shared immutable arrays. These prototype library APIs are not stable ABI promises. Python/C++ comparisons must
state numeric domains and account for value-copy and bounds behavior; all original
profiles require regression coverage. Two source expressions with fewer characters
can tokenize differently. The true best representation remains an empirical M6/M7
question.

## Status

Accepted for the user-requested M3 implementation experiment; long-term surface,
aggregate limits and systems-memory design remain open.

## Measured outcome

[The paired experiment](../../benchmarks/reports/2026-09-30/EXPR_V4.md)
records full-program counts, both tokenizer screens, compiler stages, checker cost
and native/Python/C++ execution. The 25-program corpus uses 851/906 NIL tokens
versus 1068/1068 Python tokens with fresh-local transforms. Small unrolled v3 sums
can be shorter than array loops. Numeric signatures remain provisional; model
generation/repair/TCR superiority is unmeasured.

LLVM initially copied read-only aggregates on each iteration; entry snapshots fix
that without changing semantics. Updated array state still causes quadratic copying:
at length 256 reverse/prefix are roughly 147×/105× slower than equivalent local
C++ mutation, and 3×/2× slower than local Python. Retain immutable observable values
but require alias-safe storage lowering before claiming fast bulk updates. This
backend limitation is evidence for a focused optimization task, not justification
for silently changing value semantics or adding pointers.

## Subsequent backend decision

The copying figures above describe the historical lowering. [ADR 015](015.md)
adds proven private loop storage and typed-function inlining without changing
this record's immutable semantics. Retain the original measurements as baseline.
