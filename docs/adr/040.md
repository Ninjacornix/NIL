# ADR 040 — Inline linear source-library expressions before rooting

## Context

Source std push costs the same five tokens as an intrinsic but Round 17 measures
131 ms versus 78 ms for concat inside a conditional builder. Per-call frame
reconciliation dominates. The operation must remain defined by validated NIL
source, with no runtime trust/ownership annotation or new intrinsic.

## Decision

Use a small HIR expansion before native rooting for linear leaf expressions. The
initial proof requires each parameter exactly once, every intermediate exactly
once, one dynamic parameter/result, flat Buffer/Bytes, and no calls, lazy regions,
loops, aggregates or host effects in the expanded body. This admits source push's
constant → singleton constructor → concat. It can benefit another function with
the same proved body; no spelling or std name is hard-coded in the optimization.
Unused parameters and multiple dynamic parameters are deferred because rooting
lifetimes and duplicate physical aliases need a separate argument.

Arguments remain evaluated in their existing left-to-right HIR positions.
Expansion does not substitute their expressions or duplicate/reorder them.
Copy each body instruction and its original diagnostic span, remapping IDs;
revalidate the resulting HIR. Root/last-use analyses run on that expansion.
The existing singleton/capacity/alias guard handles concat. Library source is the
single semantic definition; no extra core body is introduced.

Bounded execution keeps the original calls: removing call/return/depth ticks
would change E009/E010 observability. Both reference and bounded native use the
original validated HIR. Unbounded native may expand; test it separately against
reference values, effects, diagnostic codes/spans and quota failures. No program
surface, earlier profile or default changes.

## Forecasts

O2 same 16 MiB conditional builder, 25 rotating repetitions: source push forecast
70–90 ms and <=1.10x the identical concat expression. No token change to any
program, no intrinsic delta (35 variants). Other std algorithms stay calls because
they contain loops and repeated parameter uses. Forecast misses stay in report.

## Alternatives

Teach the runtime a push intrinsic: duplicates source semantics. Inline syntax
before argument evaluation: risks evaluation/trap order. LLVM inliner only: has
not removed the rooting boundary. Full general inlining is a larger lifetime and
budget-semantics proof and is not this decision.

## Consequences

Unbounded code generation may use different internal HIR, with unchanged checked
program observations. Bounded diagnostic/budget experiments cannot measure this
optimization. Future eligibility expansion needs its own root/quota proof.

## Status

Accepted after the independent Round 17 audit passed; committed before implementation.

## Amendment — checked flat leaf expansion (2026-10-10)

Round 24 Part B gates are green (577 debug/release, 265 sanitizers, two complete
765-family seeds, frozen corpus 2,815/original 610 and both cohorts 1,070).
Its census continues on a frozen shadow compiler; timing has finished. This
amendment is committed before Part C implementation.

The exactly-once SSA-use restriction is unnecessary for inlining: arguments
have already been evaluated left-to-right at the caller. Reusing an argument's
SSA ID does not reevaluate its expression. Allow multiple reads and unused
parameters/intermediates in small flat sequence leaf bodies. Permit Constant,
Length, Index, Replace, Binary, Compare and typed Buffer/Bytes/Concat/Slice
operations. Keep the eight-instruction bound, one dynamic Buffer/Bytes parameter,
Buffer/Bytes result and only Buffer/Bytes/i64 parameters. Bodies containing
calls, regions, aggregates or host effects remain excluded. This is a general
operation whitelist, not a matcher for swap/pop names or index shapes.

Clone body instructions in original order with original types/spans and remapped
SSA IDs. Clone expressions only at the call site, inside its existing lazy/loop
region; never move them out of a selected arm. Caller argument effects/traps
remain before body operations and occur exactly once. Revalidate the expanded
HIR, then derive rooting/liveness/borrowing facts on it. No uniqueness is assumed
from eligibility: later reads, caller aliases and parent edges retain the normal
copying/runtime root guards. Every intermediate remains tracked by those analyses.
No new alias/reuse claim is required. Resource limits may differ, under ADR 046/047.

Bounded builds still retain calls and exact instrumentation. The earlier
E009/E010 instrumentation statement above is historical and incorrect: step and
call-depth guards use **E008**, never E010. Reference retains original HIR.
Earlier source profiles and the default are unchanged.

Forecasts (25+ rotating repetitions): std/caller ratio <=1.10 for Bytes/Buffer
swap and pop. Part B medians: Bytes swap 23.710/6.446 ms; Buffer 23.945/6.827;
Bytes pop 12.901/7.222; Buffer 13.369/7.587. Forecast no significant append/scan/
transform change, no token change, 35 intrinsic variants. Std source remains the
single semantic definition. If checks/roots remain slower, publish the miss.

Tests must cover reordered/grouped/binding/helper operands, repeated indices,
live aliases, lazy selected/unselected calls, loop regions, argument effects
exactly once left-to-right, bounds/byte spans, parent children, zero-slot records
and record-buffer rejection. Show removed unbounded calls and retained bounded
calls; native O0/O2 and sanitizers must pass. Full gates rerun after code changes.

Alternatives: core swap/pop duplicates source semantics and is deferred unless
measured expansion misses parity. LLVM-only inlining left the root-frame boundary.
General recursive/aggregate/effectful HIR inlining remains outside this small step.
