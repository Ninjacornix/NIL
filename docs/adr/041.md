# ADR 041 — Core 1.0

## Context

The maintainer defines Core 1.0 by executable coverage of NeetCode 150, before
shorter standard-library solutions. Existing byte/file corpora do not establish
algorithmic coverage. This round measures the current compiler at `31cb922`;
it adds no compiler, runtime, grammar, profile, intrinsic or dependency changes.

The public names/categories are pinned from neetcode-gh/leetcode's
`.problemSiteData.json`, revision `5a3c1b2d59b4e5c6252006343d73849ebc75f796`.
There are 150 entries in 18 categories. Only names, categories and identifier
links are reused. Contracts, reference code and fixtures must be original;
LeetCode/NeetCode statements, examples, tests and solution code are not imported.

## Decision

### Completion criterion

Core 1.0 requires a verified NIL solution for **every** frozen problem contract.
Each passes all original deterministic edge, seeded and largest-size fixtures
in the reference evaluator and native O0/O2, with byte-identical output, matching
diagnostics, identical allowed host effects and unchanged input. Valid fixtures
must not trap; compiler/authoring failures, resource failures and unsupported
capabilities are separate statuses. A forecast is not a passed solution.

Solutions may use current std map/filter/fold/push/sort, modules and handwritten
helpers. No problem-specific intrinsic, opaque oracle call or precomputed fixture
answer is allowed. Index-based trees/graphs, explicit stacks, flat grids, decimal
map keys and arithmetic emulation are legitimate implementations, not missing
types by definition. Any required algorithm restriction belongs in its contract.

### Performance bound

On each largest fixture, native O2 must take **at most 3x** the median of an
original C++ reference in the same algorithm class. Use the same Clang, O2,
disabled FP contraction, 15 or more rotating warm repetitions after one warmup.
Check outputs in every repetition. Timings include process startup, file parsing,
kernel and serialization for both languages; publish min/median/max, ratios and
variance. Small constant-size problems may use a declared batch of independent
requests, fixed before authoring NIL, to make useful work measurable. No task is
shrunk after observing NIL results. A timeout or quota failure is a failed gate,
not a timing sample. Ambiguous/noisy measurements remain pending.

Threefold allows current checked immutable storage, quota and host-I/O overhead
without accepting an order-of-magnitude abstraction penalty. It is a qualification
bound, not a claim of C++ parity or an excuse for poorer complexity. C++ must not
be deliberately slowed to match a bad NIL algorithm. Algorithm, layout, I/O cost
and compiler overhead must be distinguished when the bound is missed.

### Core, STL and later work

Core 1.0 is the typed semantic execution substrate and its correctness/performance
on this suite: scalar/product/collection types, control flow, static callbacks,
local modules, checked operations, diagnostics and explicit host effects. Current
std is permitted; the definition does not require migrating it or adding a heap
intrinsic. Missing convenience operations are not automatically core gaps.

STL 1.0 follows: reusable general algorithms and codecs with smaller call sites,
source/repair-token measurements and measured native parity under ADR 035. A
handwritten helper can satisfy Core 1.0 while still exposing an STL density gap.
Concurrency, native FFI, Unicode semantics, a general regex engine, views/borrows
and runtime closures are post-1.0 decisions. The byte dot/star DP exercise is not
a requirement for a general regex library. No arena/quota/root/borrow/effect
guarantee may be weakened to reach coverage or speed.

### Default and reference limits

The default remains expr-v0. Changing it requires all qualification gates, a
consolidated versioned normative 1.0 specification, frozen syntax/semantics,
resolved chronological contradictions in the experimental spec, migration notes
and an explicit maintainer decision. Earlier named profiles remain available.

The benchmark-only evaluator helper may select up to 1,000,000,000 instruction
steps, retaining the current 256-frame depth and 64 MiB storage limit. Its limits
and 120-second execution timeout are recorded, not compiler changes. Native
correctness uses bounded execution with the same limits; performance uses the
existing unbounded mode, preserving memory/bounds/effects checks. Resource-limit
failures are reported separately from language expressibility. Iterative rewrites
are allowed; changing the compiler's depth policy is not part of this round.

### Preregistration and selection

Before any new NIL solution, commit all 150 contracts, fixtures, feature census,
per-problem forecasts and source-selection hashes in the benchmark repository.
Forecast semantic feasibility separately from expected performance qualification.
For each official category choose the two smallest SHA-256 digests of
`NIL-Core-1.0\0<CATEGORY>\0<SLUG>` (UTF-8). No replacements after seeing failures.
This gives 36 samples, including LRU Cache, Word Search II and N-Queens. Attempt
every selected problem; failures stay visible and do not enter the verified corpus.

Raw runs, unsuccessful candidates and timings stay outside git; commit original
definitions, original references, successful NIL sources and evidence summaries.
Tokenize complete standalone solutions with cl100k/o200k, record versions/bytes/
characters, and distinguish source density from total tokens to a correct program.
No model inference occurs. The existing application corpus remains frozen.

## Alternatives

Require only semantic coverage: overlooks unusable copying. Require exact C++
parity: too sensitive for whole-process qualification. Require only a small easy
sample: does not define Core 1.0. Infer missing types from Python conveniences:
confuses encoding/standard-library cost with core capability. Copy an existing
test collection: rejected by the original-assets requirement.

## Consequences

Coverage and performance remain unproven on unsampled problems. This round is a
yardstick and census, not Core 1.0 completion. Measured blockers determine later
rounds; operator spelling or hypothetical recursive types are not assumed answers.
Changes to root, ownership or quota proofs require separate ADRs and differential
validation. The list/contract hashes make future comparisons auditable.

## Status

Accepted measurement definition. Committed before suite implementation. Numerical
census forecasts are preregistered separately before NIL sample authoring.
