# ADR 021 — Allocation-free sequence returns and induction reads

## Context

Returning an unchanged sequence from a helper caused redundant roots every
iteration. Checked generic-width accesses also obstructed SIMD optimization.
No language/ownership syntax, views, LLVM changes or quota changes are permitted.

## Decision

Generalize the HIR greatest-fixed-point summary to any result type. Accepted
operations cannot allocate/collect/reallocate/mutate arena sequences or perform
host effects. Sequence results can therefore only alias input values, including
selected aliases or sequences returned through recursive calls/loops. A closed
recursive component with no sequence input cannot construct a terminating fresh
sequence under this instruction whitelist. Constants of byte type, constructors,
slices, concat, replacement, format and host operations remain rejected.

Suppress roots for inputs AND intermediate sequence aliases within a proved
function/region/loop. Its allocations remain physically resident until the next
collection, which cannot occur within that interval. At a boundary back into an
allocating caller, normal semantic last-use analysis registers live returned
aliases before any subsequent allocation. Semantic capture/last-use sets are
unchanged; no uniqueness/ownership assumption is introduced. Lazy unselected arms,
trap order, effects and budget/depth guards keep their original CFG and ordering.

For allocation-free loops only, identify a restricted induction class: the exact
condition is index < length(sequence); the sequence is identity-carried; index
starts at a nonnegative constant and advances by exactly one. In each body,
0 <= index < length <= 64 MiB, so the next increment cannot overflow i64. The
existing condition remains the upper-bound check; nonnegativity is proved once
from the initial value and induction, with no newly hoisted failing trap. Empty
and oversize-start loops execute no load. Only accesses to that exact sequence/index
SSA pair qualify; computed starts, shifted indices, other conditions and changing
sequences keep nil_get. Facts apply only on the body edge, never the exit/finish.

Compute data pointer in the preheader and emit typed i8/zext or i64 loads in the
body. C static assertions enforce offset 40 and alignment 8 of the private native
header. Byte loads use align 1, buffer loads align 8. Do not assert noalias (aliases
are legal), or constant dereferenceable payload size (empty values are legal).
Unproved bounds, byte, quota and parse semantics stay in C. Proved direct loads
now also depend explicitly on HIR type/range invariants and this private ABI.

## Alternatives

Views would change slice semantics and are excluded: v5 slice copies/allocates.
A general range solver or runtime-versioned computed-index loops is deferred.
Hoisting a potentially failing access check into a zero-trip/lazy preheader changes
observability and is rejected. LLVM fork/library integration and unsafe Rust are
unnecessary. A failed proof simply retains the checked path.

## Consequences

Alias-returning helpers can borrow even without inlining. Allocating/conditionally
allocating callees stay conservative. Direct loads give LLVM a canonical loop to
vectorize; actual emitted IR, assembly and measurements are recorded separately.
This does not promise SIMD for bounded execution, recursion or every loop shape.
