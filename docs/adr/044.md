# ADR 044 — Guarded read replay and interprocedural ownership

## Context

Round 22 starts at main `92d62b3`, benchmarks `84a20fc`. The corrected fuzz
census is committed before this decision (`eab1320`, benchmarks `76af011`).
Natural qualification is 19/150; tuned is 22/150. Natural native O0 payload
traffic is 2,086.6 GB, including 1,926.6 GB REQUIRED and 160.1 GB AVOIDABLE.
REQUIRED describes later reference observations, not an impossibility theorem.
Frozen natural sources and the 114 held-out problems remain untouched.

## Decision — preregistration

### G2: guarded read replay, primary

Use a dataflow plan over typed SSA operations, not expression spelling or
structurally identical indices. For a replacement, find all subsequent scalar
computations up to the original value's last consumer. A speculative read replay
may compute their values before the write, only after the replacement's own
bounds, byte-range and prospective quota checks. Replay must not trap, allocate,
change roots, perform host effects, or observe quota. It returns validity and
cached scalar values. Bounds failures invalidate the plan rather than emit a
diagnostic. The original copying execution remains the fallback.

Replay follows selected lazy arms only. Read-only scalar callees may be replayed
from their actual validated bodies; declarations are insufficient. Calls and
recursion use a finite compilation/replay expansion budget. An unsupported
operation, exhausted expansion, allocation, host effect, escaping result, or
unavailable dependency makes the plan invalid. No call may be executed early
merely because the existing borrowing summary says it does not allocate:
borrowing permits bounds, division and parsing traps.

On success, the checked update may use the existing physical uniqueness guard,
and later scalar consumers use the cached results. Root counts still decide
whether aliases require copying. On failure, no original operation is removed
or reordered. Read replay cannot cross an allocation/quota observation even when
its read bounds are safe: the original and replacement would have distinct live
charges in the reference execution. It cannot cross a host effect.

Bounded execution retains ordinary operations and existing snapshot behavior.
Removing replayed calls or reads changes E008 instruction/call accounting; native unbounded
optimization alone may use this plan. No new limits or stack-safety claim.

### G1: interprocedural last use, secondary

Analyze parameter provenance and returned aliases with a monotone fixed point.
Unknown callees and recursive components start conservative. Record fields and
map/record-buffer children propagate reachability; branch summaries union both
possible arms. Calls are not last uses just because their results are scalars.
The caller may surrender an argument only after left-to-right argument
evaluation and only when no future caller or escaped descendant can observe it.
The callee installs parameter roots before collection. Runtime uniqueness remains
mandatory. A returned alias remains live until its caller's final consumer.

Do not ship G1 if a provenance summary cannot connect a keeping read to the
actual physical child/root edge or preserve the reference quota observation.
Publish that boundary rather than a new call-shape recognizer.

## Eight obligations and required evidence

| ADR 043 obligation | G2 argument / admission requirement | G1 argument / admission requirement |
|---|---|---|
| 1 Live aliases at observations | No root changes in replay; existing roots and uniqueness guard retain other aliases | Proven last-use handoff; synchronize at unchanged observation points |
| 2 Returned aliases | Only scalar cached results; sequence results force fallback | Returned parameter/child origins propagated to callers, never marked dead |
| 3 Lazy arms | Replay selects one arm; invalid/effectful arm falls back; no speculative effect | Union summaries, selected execution only |
| 4 Recursion | Finite replay budget; exhausted or unproved call falls back | Monotone fixed point, no acyclic-only inference |
| 5 Record/map children | Existing child edges force copying; never remove a parent for a scalar snapshot | Full typed child provenance required; unknown descendants conservative |
| 6 Trap/effect order | Original update checks first; replay guards never trap; no crossing host effects | No scheduling implied by last use; original evaluation/check order |
| 7 Quota observations | Retain reserve-as-if-copying; no intervening allocation/observation while versions share storage | Preserve exact charge/death boundaries, not just final returned values |
| 8 Deferred and recycled roots | Slot/mirror protocol unchanged; no observed-frame admission from replay alone | Handoff updates slots, mirrors reconcile normally; relocation and child roots retained |

These are proof obligations, **not claims already established by implementation**.
Acceptance requires O0/O2 differential and sanitizer evidence over reordered
operands, bindings/inline expressions, nested conditionals, reads in every
position, aliases through callees, returned aliases, recursion/mutual recursion,
record/map children, selected/unselected lazy arms, unsafe read traps and effects.
Any unproved case retains copying; no narrower shape recognizer is substituted.

## Copy hints

ADR 043(c) remains the contract: opt-in `--explain-copies`, machine-readable
records for actual copy sites with the span of a keeping read. Deterministic,
no change to stdout, host effects, diagnostics or exit status. A conservative
static candidate is not an actual runtime copy: do not label it as one.
Unknown alias/child provenance must be reported honestly rather than supplying
the update span as an invented keeping-read span.

## Alternatives

Unconditional read hoisting changes which bounds trap wins. Reordering calls
based only on borrowing admits trapping callees. Reusing storage solely on a
last-use count breaks returned/child aliases. Deferring writes or maintaining
virtual sequence overlays would need a different runtime and quota proof;
rejected here. Hand rewriting natural sources is forbidden. Full dynamic views,
ownership syntax, raised limits and a new execution model are out of scope.

## Consequences

G2 and G1 implementations must be separate commits after this ADR. HIR remains
syntax-independent and first-order. No intrinsic, syntax, default profile or
earlier-profile change. Failed proof obligations stop the affected analysis;
measurements and the conflict still ship. Configurable limits/native stack
safety from ADR 043(a)/(b) remain deferred, explicitly outside Round 22.

## Status

Accepted as an experimental design and admission contract before implementation.
The preregistration itself enables neither analysis. The later admission result
below accepts guarded G2 with fallback and defers G1; the measured natural
qualification remains 19/150 (tuned 22/150), with REQUIRED bytes reduced 17.9%,
below the forecast. See the [Round 22 report](../../benchmarks/reports/2026-10-08/ROUND22.md).

## Admission result: G1 remains deferred

G2 has a runtime fallback and a finite nontrapping evaluator over validated HIR.
The general SSA interval accepts reordered indices, bindings, readonly callees
and selected nested lazy arms. Unsupported operations invalidate replay rather
than acquiring a new expression-shape recognizer. In particular, a second update
is an allocation/quota barrier even when all later reads are bounds-safe.

The regression `:s=b(!bytes(22369590,97))` with body
`(s):s=a[0:90][1:a[2]][2:a[0]]` needs three live semantic capacities at the second
write and traps E013. Reusing the first write while the old read crosses that
second write would retain only two physical charges and incorrectly succeed.
Existing reserve-as-if-copying checks cover one result; they do not represent
arbitrarily many simultaneously live immutable versions. Guarded replay therefore
falls back before this barrier. This invalidates the optimistic heap forecast;
it does not justify moving the quota observation.

G1 is **not implemented or claimed proven**. A greatest fixed point saying a
callee borrows is insufficient to identify which caller root or child edge can
be surrendered at which observation. Returned aliases, a sequence held in a
live parent, and alternative lazy arms require provenance across frames and a
logical charge/death proof. The current source-value last-use table cannot
express those edges, and removing their roots can change E013 before the old
semantic version dies. No callee-shape matcher or branch-specific root deletion
is substituted. The explicit eight-obligation contract remains open for G1;
its conditional forecast contributes zero gains this round. This is a soundness
boundary, not evidence that general G1 is impossible.

The copy-hint prototype reports actual successful C-runtime payload copies with
local keeping-read spans where proven. Unknown provenance is null; the complete
ADR 043(c) cross-frame keeping-read contract is not fulfilled by this prototype.
No claim of exhaustive copy-site coverage is made.

A second concrete boundary covers G1 child provenance. With
`record Holder(text:s,n:i)`, entry `:s=b(Holder(!bytes(33554392,97),0))`, and
`(Holder):s=changed=a.text[0:90];temp=#!bytes(100,0);n=a.n;changed`, the old
text is never read again, but the live parent retains its charge until `a.n`.
The first replacement fits exactly; `temp` traps E013 at the `!bytes` allocation.
Reference and native O0/O2 agree. Releasing the parent's unused text edge on the
basis of future payload reads alone would incorrectly make that allocation fit.
Preserving a separate logical charge could address this, but the present root
protocol does not supply that proof. The regression records the quota boundary
without claiming it proves G1 impossible.

## Copy-explanation follow-up contract

The diagnostic instrumentation may maintain a parallel, stack-owned root metadata
table only when `--explain-copies` is enabled. It must never retain, release,
reconcile, allocate arena storage, or influence uniqueness. At a successful
payload copy it may inspect existing root slots and acyclic record-buffer child
edges to identify a *retention use* across frames. This is not a G1 admission:
a root retaining storage is not proof that its later use observes that payload.

Report `keeping_read` only for the existing proved direct local read. Add a
separate `retaining_use` span for conservative root retention, including a live
parent's scalar field access, and label the distinction. Never relabel the
latter as a semantic payload read. Missing provenance stays null. Report each
copy kind at a site independently; zero-byte work is not payload copying.
Cover map key/value extraction and replacement materialization, which the
initial prototype omitted. Compiler-created SSA aggregate moves and allocator
relocation are not runtime payload-copy observations; retain this limitation
explicitly. This follow-up improves diagnostic coverage without claiming the
complete cross-frame *semantic keeping-read* contract is discharged.

### Diagnostic terminology correction

Post-validation source audit: E008 covers instruction-budget and call-depth
exhaustion; E009 covers arithmetic failures (for example division by zero).
The original preregistration incorrectly grouped E009 with execution ticks.
This corrects documentation only; no code, limits, forecasts or diagnostic
behavior changes.

## Maintainer clarification: nullable keeping-read contract

On 2026-10-08 the maintainer accepted **nullable `keeping_read` plus a separate
`retaining_use` and reason**, rather than requiring a full semantic-observation
trace in Round 22. This resolves the diagnostic contract; it does not accept G1
or claim that root retention proves a future payload observation. An AVOIDABLE
copy or a child retained only through its parent's scalar field may have no
later payload read to name. Inventing one would contradict the copy census.

Add an explicit `reason` tag to each existing hint record:

- `later-local-read`: the existing direct local index/length candidate supplies
  `keeping_read`; not a claim that it is the sole alias forcing the copy.
- `live-root-retention`: an existing root reaches the source and supplies
  `retaining_use`; `keeping_read` may be null.
- `required-materialization`: this path transfers an input/row/key/value into a
  result, rather than copying an old left operand for update.
- `unresolved-copy-cause`: no proved local read or bounded retention provenance;
  keep missing spans null. This is not evidence that the original is dead.

These tags classify the diagnostic evidence, not semantic copy necessity.
The amendment is committed before its renderer change. The C renderer remains
inside `NIL_EXPLAIN_COPIES`; default code, roots, quota and evaluation are unchanged.
Existing tests must additionally assert E013 at the exact two quota-witness spans;
reference/native agreement alone would not prove that the witnesses fail.

G1 remains stopped under Round 22's explicit soundness condition. Its missing
alias/child and logical-charge proof is published above. Configurable limits and
stack safety remain outside this round. Full semantic-observation tracing is a
possible later diagnostic extension, no longer a Round 22 requirement.
