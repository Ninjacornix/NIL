# ADR 049 — Inferred root ownership and selected scalar continuations

## Status

Preregistered 2026-10-10, before Round 25 compiler changes. Each class is admitted
only after its own proof/variant matrix, debug/release, sanitizer, differential,
corpus and depth gates pass. This document specifies a design, not completed proofs.
Stop at a completed class if a later class cannot discharge its obligations.

## Industry basis

Lean's [Counting Immutable Beans](https://arxiv.org/abs/1908.05647) describes
borrow inference and reset/reuse for nonshared functional values. It motivates
separating logical immutable values from physical storage ownership; it does
not prove NIL's arena or deferred-root protocol.

[Koka Perceus](https://doi.org/10.1145/3453483.3454032) combines precise reference
counting and reuse analysis. Its [implementation overview](https://koka-lang.github.io/koka/doc/book.html#sec-reuse)
reinforces specialization before ownership analysis, rather than inferring safety
from an opaque call or a syntax spelling.

[Swift parameter ownership](https://github.com/swiftlang/swift-evolution/blob/main/proposals/0377-parameter-ownership-modifiers.md)
separates consuming and borrowing contracts. `_modify` accessors motivate scoped
interior access, but no arbitrary interior pointer or accessor is added here.
[Rust `mem::take`](https://doc.rust-lang.org/std/mem/fn.take.html) transfers a
child while replacing its owner-visible slot. NIL instead may clear an internal
root slot only after proving its old logical owner unobservable. This is an
inferred compiler fact, not a user-visible empty field or new ownership syntax.

## Decision

Use general typed SSA liveness/provenance, selected-region continuations and
runtime uniqueness checks. No benchmark name, source spelling, index equality
pattern or hand-written natural rewrite is an admission criterion. All additions
are native lowering/analysis; no new intrinsic, type, grammar or default-profile
change. The intrinsic enum remains 35.

### R1 — path-sensitive scalar continuation snapshots

For an update, identify every remaining observation of the original in the
current scope and its selected nested lazy regions. Trace the scalar dataflow
backward; retain bindings as SSA dependencies. A loop's next-state handle is
an ownership continuation, not automatic escape. A handle passed/stored/returned
to any independent live owner remains an alias and prevents root retirement.

Snapshot only pure scalar observations whose dependencies are available. Preserve
selected-arm control flow: never execute an unselected arm's effects, calls,
allocations or traps. Guarded probes may perform nontrapping checks/loads; an
invalid bounds probe yields an invalid snapshot, never a diagnostic. Guard failure
retains the original root and ordinary copying execution. Original update checks
and all fallback diagnostics stay at their original code/span/order. Unsupported
instructions or a bounded replay budget cause conservative fallback, not an
inferred absence of observations.

Cached scalar values replace only their proved original observations. Retire the
loop/outer-scope root on the valid selected path only when all future observations
are cached, with a still-rooted local owner protecting the allocation. A returned
alias or unsnapshotted descendant remains rooted. Runtime root-count uniqueness
still decides reuse; extra aliases must copy. Existing bounded execution retains
instruction accounting; unbounded optimization does not redefine E008.

Alternative: postpone physical writes until all observations complete, keeping
checks at their original sites. This can be sound for unobserved new versions,
but general mixed-version consumers require overlays and additional materialization
logic. Prefer scalar snapshots; do not ship a delayed-write recognizer as a
substitute for the general continuation proof.

### R2 — parameter ownership and return provenance

Compute per-function, per-parameter facts from validated bodies: borrow-only versus
may consume/update, and possible returned parameter/child origins. Propagate origins
through selected regions (static union), loops and record fields. Solve recursive
and mutually recursive call-graph SCCs to a monotone fixed point over finite origin
sets. Unknown origins/callees stay conservative. Never infer borrowing from purity
or no-allocation alone: existing operations may trap.

At a call, all arguments evaluate left-to-right before ownership handoff. Transfer
an argument's caller root only after its last observation, including proved cached
scalar continuations. Repeated arguments, independently retained return aliases,
parents and descendants keep their separate roots. The callee installs owning
parameter roots before any collection/uniqueness observation; an allocation-free
borrow may not outlive its owner. Returning an alias transfers a live obligation
back to the caller; it is not evidence that the parameter was fresh.

Recursion cannot release an ancestor's still-observable value. SCC facts must
include those reads; runtime uniqueness handles remaining dynamic sharing. Static
HOFs use their specialized bodies only when their provenance is available; unresolved
callback/unknown dispatch stays conservative. No declaration can promise ownership.

### R3 — dead record child edge

For a record whose last logical use is reconstruction, identify a projected child
and every later observation of that child and parent. Cache eligible scalar
observations first under the R1 rules. Root the projected child before clearing
exactly the old parent-field root slot on the admitted path; do not modify the
SSA record value. Update under runtime uniqueness, then root the rebuilt record.
Other fields, duplicate child fields and other parents retain their own edges.
Parent reads after reconstruction or unknown child escape prevent this transfer.

**Scope:** flat Buffer/Bytes children and statically nested record paths are targets.
Map-held values and record-buffer rows stay conservative in this round: their
runtime container edge tables differ from by-value record root groups and require
separate extraction/layout proofs. Their alias interactions are negative tests.
No map/row child is dropped merely because its container looks dead locally.

## Soundness obligations for every class

1. **Aliases:** retire only the identified owner edge; every independent owner remains
   counted. Uniqueness is checked at mutation, never asserted from liveness alone.
2. **Return/escape:** propagate parameter and child origins; multiple returned/stored
   owners keep independent roots. Unknown origin is conservative.
3. **Laziness:** snapshots select arms using available pure conditions; invalid or
   effectful dependency means fallback. No selected effect is moved or duplicated.
4. **Recursion:** finite monotone SCC inference; no optimistic acyclic shortcut.
   Probe expansion has a hard budget and falls back at exhaustion.
5. **Children:** track typed field paths and root-group members, not pointer equality
   as a provenance proof. Shared parents/fields and container edges remain live.
6. **Diagnostics/effects:** all real checks remain in original order and spans.
   Invalid speculative probes never trap. Simultaneous chains follow ADR 048;
   bindings and explicit read/call/control boundaries retain their semantics.
7. **Resources/GC:** ADR 046/047 resource failures remain ordinary. A transfer gap
   contains no allocation/collection; the destination root exists before the next
   sweep. Raising limits jointly uses Round 24's exact escalation rules, including
   the hard failure for persistent native-only E013 after original reference success.
8. **Root protocol:** ordinary `nil_root_store` updates slot state and dirty tracking;
   ADR 038 reconciles before every observation. Do not edit committed mirrors directly.
   ADR 039 observed-frame paths are invalidated when a new edge changes. Recycled
   slots have exactly one owning obligation. ADR 040 expansion runs before analysis;
   ADR 044 probes preserve fallback roots; ADR 047 guard-page handling is unchanged.

Failure exits need no resumed program state, but every effect before failure must
retain its original ordering. A stack guard catches only guard-page faults.
Root changes must never turn another memory fault into an accepted resource outcome.

## Variant matrix and negative cases

Each shipped class must cover argument order, nesting, bindings/inline equivalents,
extra parameters, different/computed indices, mutual recursion and unrelated reads.
Positive IR evidence must demonstrate the mechanism rather than LLVM inlining alone.
O0/O2 tests and fuzz must retain copies for: original read after a call; `f(a,a)`;
returned alias used twice; parameter stored in record/map; callback buffer argument;
parent observed after child update; child shared by two parents; unselected lazy arm;
recursive ancestor re-read. Add an explicit effect/trap dependency fallback and
allocation/collection after every accepted handoff, plus empty/zero-slot layouts.

A conservative case is permitted only with its missing proof fact stated; a narrow
source-shape success does not satisfy the general-analysis gate. An unexplained
non-resource divergence or sanitizer finding stops admission of that class.

## R2 design settlement — 2026-10-10

This addendum settles the design points the R2 section above left open, before
the code it governs. It adds no forecast and claims no measurement. Where this
addendum is narrower than the R2 section, the narrower rule is what ships; the
unimplemented remainder stays conservative and is named here.

### Observed starting state

At `fc6c279` the caller of the R2 witness roots its loop-state sequence and does
not retire that root across the call, so the callee's `nil_set_unique` observes
two roots and copies. The existing emitter already retires an argument root
immediately before a `Call` when semantic liveness makes the call the argument's
last use. R2 is therefore not a new transfer mechanism: it is an extension of
*which* calls qualify as a last use, plus the summary that makes surrender safe.

### Parameter ownership summaries

Two per-function facts are computed from validated HIR, after ADR 040 expansion
and before lowering:

- `owns[f][k]`: function `f` installs an owning root for parameter `k` that
  covers every allocation and collection in its body. Defined as parameter `k`
  being semantically live in `f` and `f` not being an allocation-free borrow
  function. These are exactly the conditions under which the existing emitter
  roots a parameter, so the summary describes lowering rather than predicting it.
- `origins[f]`: the set of parameter indices whose storage the result of `f` may
  alias, plus an explicit unknown marker. Computed over result provenance:
  a parameter is its own origin; `Replace`, `Field` and `UpdateField` inherit
  their subject's origins; an `If` takes the union of both arms' results; a
  `Call` substitutes the callee's origin set through its arguments; a fresh
  allocation has no parameter origin; anything else is unknown.

`origins` is recursive, so it is solved as a least fixed point over finite
subsets of parameter indices, starting empty and iterating the whole call graph
until stable. This terminates for direct and mutual recursion without any
acyclic shortcut, discharging obligation 4. `owns` is not recursive; it is read
from the existing greatest-fixed-point borrow analysis.

Unknown origins are not treated as "no origin". A `PluginCall`, an unresolved
callback and any operation outside the list above all yield unknown, and unknown
blocks transfer. No declaration, purity claim or absence of allocation is
accepted as evidence of borrowing.

### Transfer admission at a call

A caller may surrender its root for a Buffer/Bytes argument `v` at call position
`p` to callee `f` in parameter slot `k` only when all of the following hold.
Each is a rejection, not a heuristic ranking.

1. `v` occupies exactly one argument slot of that call, compared by SSA identity.
   Repeated arguments keep their separate roots, so `f(a,a)` never transfers.
2. `owns[f][k]` holds, so the callee's own root covers the transfer gap. An
   allocation-free borrow callee never qualifies: it installs no parameter root
   and cannot update a sequence, so transfer would be both unsafe and pointless.
3. `origins[f]` is known. An unknown returned provenance blocks transfer even
   when the parameter itself looks dead.
4. Every use of `v` after `p` is a scalar observation admitted by the R1 rules
   and is snapshotted. A sequence-typed consumer, a region result, an escape, an
   unsupported instruction or an exhausted budget rejects the call. Semantic
   liveness unions lazy-arm captures, so a read of `v` inside an unselected arm
   still counts as a use and is covered by the same proof.
5. The caller holds an actual root slot for `v`. With no slot there is nothing
   to surrender and the call is left alone.
6. The build is unbounded with wrapping arithmetic, matching R1. Bounded builds
   keep their instruction and depth observations and never transfer.

Returning an alias of `v` is explicitly *not* a transfer condition. It transfers
a live obligation back to the caller, which the caller discharges by rooting the
call result in the ordinary way. It is never read as evidence that the parameter
was fresh, and it never licenses skipping or recycling the result's root slot.

### Ordering, effects and the transfer gap

Arguments evaluate left-to-right and complete before any handoff, as ADR 048
requires; R2 moves no argument evaluation, trap or effect. Snapshot probes are
emitted after the final argument and before the call, so they observe the
pre-call contents that the caller's later reads are entitled to see. The root is
surrendered only on the path where every snapshot is valid, immediately before
the call; an invalid snapshot retains the root and runs the original reads at
their original spans. Probes never trap and never diagnose.

The resulting gap between surrender and the callee's parameter root contains no
allocation and no collection, because parameter roots are installed at callee
entry ahead of the body. This discharges obligation 7 for R2. Obligation 8 is
unchanged: surrender is an ordinary `nil_root_store` of null, with no direct
edit of a committed mirror.

Uniqueness remains a runtime decision at the mutation. Transfer only removes one
caller root; a record child edge, a map container edge, a second caller alias or
a callee-side store still raise the observed count and still force a copy.

### Named conservative cases

Transfer is refused, with the missing fact stated, for: record, record-map and
record-buffer arguments, because their container edge tables are the deferred R3
and map/row work; map-held values and record-buffer rows for the same reason;
plugin and unresolved-callback callees; bounded builds; checked arithmetic; any
caller use of the argument that is not a proved scalar snapshot. These are
negative tests, not pending optimizations, for this round.

### Not claimed

This addendum does not claim that R2 reaches its forecast, that the witness
improves, or that R3 follows. It fixes the admission rule and the summary
lattice so the implementation can be audited against a written contract. If the
scalar continuation at the witness cannot be admitted, R2 stops and the reason
is published as a measured negative result.
