# ADR 015: private storage for proven sparse loop updates

## Context

Immutable aggregate replacement initially copied an entire array for every element
update. Length-256 reverse/prefix kernels were about 147×/105× slower than fresh-local
C++ in the historical v4 experiment. Changing source semantics would invalidate
aliases and simultaneous loop updates. Compact source alone is insufficient.

## Decision

Analyze validated HIR def-use chains independently of surface syntax. An array loop
state qualifies when its next value is a chain of replacements rooted in the old
state, and each replacement result has exactly one consumer. Conditional chains
qualify only when both branches satisfy the same proof; identity branches qualify.
An additional consumer or unsupported operation retains aggregate-value lowering.

Allocate a separate private buffer for each qualifying state in the function entry
block and initialize it on loop entry. Read old state throughout the body. Evaluate
indices, values, bounds checks, branch conditions and accounting at their original
positions. Record writes and commit them in order after all body expressions and
the body yield have completed. Guard conditional writes with their selected branch;
inactive writes never access storage. This preserves aliases, lazy traps, parallel
state updates and repeated-write order. Never mutate parameter snapshots.

Typed functions are internal behind the flat entry bridge and carry LLVM's
`alwaysinline` hint, allowing aggregate marshaling/copies to disappear. Existing
all-i64 function ABI remains unchanged. No pointer/alias promises or source grammar
changes are introduced. All header phi instructions precede storage loads.

## Alternatives

Keep aggregate copying; change arrays to mutable references; specialize benchmark
programs; introduce another backend. These either miss the measured performance
requirement or change semantics/scope unnecessarily.

## Consequences

The proof is conservative and copying remains possible for escaping intermediate
arrays. Native regression tests cover old-value reads, aliases, nested loops and
branches, zero-length arrays, repeated writes, traps and exact bounded accounting.
Seeded independent wrapping oracles exercise O0/O2 with and without budgets.
Performance claims require per-kernel results against fresh-local C++ with identical
drivers; they do not establish model-generation success or TCR.

## Status

Accepted implementation experiment. Supersedes ADR 014's observed loop-copying
limitation, not its immutable value semantics. Final measurements are recorded in
the storage benchmark report; historical measurements remain intact.
