# ADR 025 — Deterministic sorting and snapshot iteration

## Context

ADR 024 attributes the external cl100k +650 tokens to explicit algorithms, not
identifier spelling. Grade School, Connect and ETL contribute +523. Freeze the
32 external paired sources at benchmark commit `920e510`. Whole-source lexical
prototypes in [the forecast ledger](../../benchmarks/reports/2026-10-03/V5_ALGORITHMS_FORECAST.json)
are unverified until implementation and unchanged-oracle validation.

| Rank | Candidate | Gemma saving | Qwen | cl100k | o200k |
|---|---|---:|---:|---:|---:|
| 1 | Deterministic sorting of sequences/maps | 299 | 208 | 205 | 203 |
| 2 | Snapshot element/entry iteration | 211 | 159 | 159 | 151 |
| 3 | Standalone lexicographic comparison | 85 | 62 | 62 | 57 |
| 4 | ASCII classification | 83 | 73 | 53 | 49 |

Sort removes Grade School's repeated minimum selection and lexicographic helpers;
ETL switches to sorted map keys instead of scanning the ASCII alphabet. Iteration
replaces eligible full sequence scans with element/index binding and, after sorting,
map scans with key/value binding. Classification prototypes replace existing
alpha/alnum predicates, not identifiers. Comparison removes Grade School's final
byte comparator helpers but is subsumed by sorting and is not additive.

**Joint sort + iteration forecast: 553/401/398/388 tokens** in tokenizer order
above. Each's marginal contribution after sort is 254/193/193/185. These are
whole-program counts, not sums of overlapping estimates. Original 24 references,
all tasks/oracles/goldens and every baseline remain unchanged. Implement only
sort and each. Connect's graph algorithm remains; no grid-specific primitive.

## Decision

Only expr-v5 gains the two operations below. Existing programs retain their
meaning. No new type, profile, user comparator, higher-order value or module.

### `sort(data, order) -> same type`

Typed HIR intrinsic accepting Buffer, Bytes, MapI64 or MapBytes plus i64.
For sequences, order 0 is ascending and 1 descending; integers compare signed
without subtraction overflow, bytes unsigned. For maps, 0 compares owned byte keys
lexicographically; 1 compares values (signed integer or unsigned lexicographic
bytes), then keys ascending. Prefix sorts before extension. No locale/Unicode.

Sorting returns an immutable value retaining its input's semantic capacity. Map
iteration reflects the sorted order; lookup associations remain intact and later
insertions append. The composite map comparator includes unique keys, so equal
values are deterministically key-ordered, not arbitrarily permuted. Equal primitive
sequence elements have no identity and remain observationally indistinguishable.
The result matches stable sorting under this complete comparator; no value-only
stable insertion-order mode is implied. Duplicate insertion remains E020.

Arguments evaluate left-to-right. Invalid order (not 0/1) fails E012 before full
result-capacity reservation E013, including empty/single inputs. Reserve the same
input-plus-result charge even when storage can be reused. Existing last-use proof
and runtime root uniqueness permit in-place sort, otherwise copy. An allocation-free
O(n log n) native heapsort uses constant scratch; no uncharged n-sized workspace.
Map entry swaps retain owned byte offsets and rebuild the hash index once. Reference
sorting uses owned/COW storage and independent Rust ordering. No host effect.

### `each(input, state*; step*; finish)`

A typed structured control operation, lowered canonically to existing HIR Loop
regions. Input is Buffer, Bytes, fixed array or either map; at least one user state.
Evaluate input once, then initial states left-to-right. Retain an immutable snapshot
through the whole operation. Visit sequence indices/insertion-order map entries
exactly once, without early exit. An empty input executes finish directly.

In step, `a` is sequence index (i64) or map key (owned Bytes), `b` is sequence element
(i64) or map value (i64/owned Bytes); `c`, `d`, ... are user states. All next states
are evaluated left-to-right from old bindings, then committed simultaneously. Step
returns exactly one result per state with unchanged types. Finish binds only user
states as `a`, `b`, ... and returns one value. Nested each/loops shadow bindings in
their own regions; lazy arms keep the current region bindings.

Snapshot length/order cannot change when a step returns a replacement/update of an
alias. Map keys are copied first (E013), then byte values copied (E013), before
executing that iteration's user step. Integer values and sequence elements allocate
nothing. These materializations occur even if the step ignores a binding; quota
traps remain observable. Each introduces no other execution error; body/finish
traps/effects retain existing order. E007 rejects noncollections/state-type mismatch;
E006 rejects wrong state result count; malformed region syntax E001. Each is not
recoverable I/O or a plugin-specific parser extension.

Canonical lowering carries hidden snapshot and nonnegative index, tests index
against snapshot length, binds checked elements/owned entries, computes user steps,
and advances index. Existing typed HIR validation, evaluator/native Loop execution,
root tracking, lazy regions and last-use proofs remain the semantic implementation.
Append/update user states retain their reuse proofs; snapshot aliases stay live and
force copying where necessary. No mutation or unchecked access escapes to source.

## Alternatives

Comparison and classification are smaller forecasts; comparison overlaps the winner
and classification does not address the largest tasks. Do not implement either.
Records, callbacks, generic comparator syntax, parsed JSON frameworks, iterator/view
objects and a grid library are outside this round. Sorting the same n-element value
on every iteration still costs O(n log n) each time; reuse eliminates copying, not
algorithm work. Maps with byte values still pay owned copy costs during iteration.

## Consequences

Predicted external cl100k gap falls from 650 to 252 (+5.00% vs Python) if every joint
prototype passes. This is a forecast, not a measured result or model-efficiency
claim. Compare actual per-task and marginal savings; retain losses and shortfalls.
Run O0/O2 parity including quota/order/aliases, both sanitizer suites, three seeds,
old and new reference corpus oracles and scaling. Keep unsupported tasks rather
than implying sorting solves Unicode, floats or search/adapter requirements.
