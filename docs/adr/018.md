# ADR 018 — Checked v5 application runtime performance

## Context

The live-storage implementation made file transforms feasible but measured
57.498 ms at 1 MiB and 887.161 ms at 16 MiB. The supplied profile attributes the
cost to byte-at-a-time reads/quota checks, opaque cross-TU accessors, repeated
length queries, and shadow-root transfers. Immutable values, E012–E018 ordering,
the 64 MiB live/transient quota and earlier profiles must remain unchanged.

## Decision

Read regular files using `fstat` capacity hints and `fread`; grow for streams.
Use actual received bytes rather than the hint to enforce the budget. Retain
E013 priority for an oversized successful prefix and E015 for other read/close
failures. Publish the scratch payload into the arena only after successful I/O,
so regular-file reads need no second full-file allocation/copy.

Compile v5 O2 IR and its C runtime with full LTO and explicit always-inline
checked accessors/root updates. **C remains the single source of truth** for
native element-access semantics; the emitter does not duplicate bounds, byte,
quota or alias checks. O0 retains separate compilation. Linux application O2
requires LLD; macOS uses its system LTO linker. Missing tooling fails explicitly.

Maintain root counts and live-byte totals through one slot-update primitive.
Collection frees zero-root payloads at allocation boundaries; never during a
root-transfer gap. Replacements check live bytes/root count in constant time.
Retain one root slot across proven straight last-use state chains; otherwise
keep the conservative protocol. Hoist only lengths proven preserved by identity
or replacement chains, and remove repeated clears of already-dead SSA roots.
See [root and read invariants](../architecture/DYNAMIC_STORAGE.md).

## Alternatives

Hand-emitting LLVM loads/stores would make layout/check semantics duplicated
and harder to maintain. LTO without explicit inline attributes left accessors
out of line in the local binary. Removing checks, increasing the quota, eager
free-on-last-root, views and ownership syntax violate this workstream's scope.

## Consequences

Optimized application builds need an LTO-capable toolchain and move optimization
work into linking. The reference evaluator and private native runtime differ
physically while retaining the same observable diagnostics/effects. Complicated
loops may still copy or transfer roots repeatedly. The performance evidence is
one cached-file workload, not a general C++-parity claim.

## Status

Accepted for the experimental expr-v5 application core. See
[validation](../validation/APPLICATION_RUNTIME.md) and the
[measured report](../../benchmarks/reports/2026-10-02/APPLICATION_RUNTIME.md).
