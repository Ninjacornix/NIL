# ADR 047 — Stack exhaustion is an ordinary resource failure

## Context

Maintainer decision, 2026-10-09 (Round 24): stack exhaustion follows ordinary
memory exhaustion. Round 23 did not admit B4's exact native-depth proof. Its audit
found unbounded O0/O2 crashes and bounded O0 large-record stack overflow. This ADR
supersedes ADR 043/046's exact stack/depth-equivalence admission requirements;
immutable values and every non-resource diagnostic/effect guarantee remain.

## Decision

Every native executable runs its existing program driver once on a dedicated
POSIX thread with a caller-selected mapped stack. Default usable stack: **32 MiB**;
Rust `Options.stack_bytes` and CLI `--stack-size BYTES|KiB|MiB` select it. Minimum
64 KiB; round upwards to the OS page size. Two inaccessible guard pages surround
the mapping. This is execution machinery, not language concurrency or a sandbox.

Install a SIGSEGV/SIGBUS handler with SA_SIGINFO/SA_ONSTACK. The worker installs
its own 64 KiB alternate signal stack before running NIL. Convert a fault only
when `si_addr` is inside the mapped guard pages: async-signal-safe `write` emits
`E008 call depth/stack exhausted`, then `_exit(1)`. No guessed source span.
Every other fault restores the prior signal disposition and remains a real
failure; preserve an existing sanitizer handler. Test an actual non-guard bad
access independently, not just the address predicate.

Large frames must not jump past a guard. Enable native stack probing for emitted
LLVM definitions and generated C: Darwin `__chkstk_darwin` / `-fstack-check`;
Linux inline stack-clash probes / `-fstack-clash-protection`. Verify emitted code
and the large-record O0/O2 witness; an unsupported backend must fail explicitly,
not silently generate unprotected large frames. No unsafe Rust or new dependency.

Bounded execution retains its existing instruction/depth counters, with the
obsolete depth-256 build restriction removed. Defaults for reference and bounded
native call depth become **16,384**, selectable through existing Rust limits/options;
tests/fuzz explicitly retain small limits. Reference frames already live on the
heap. Physical stack exhaustion may precede a logical counter or occur at a
different depth. Exact E008 instruction/span is not language semantics.

Differential comparisons with clean **E008 or E013 on either side are
INCONCLUSIVE**, counted separately by code and family. Signals, timeouts, build
failures, malformed diagnostics and sanitizer findings are always failures,
including when the reference reports a resource error. All other codes/spans,
outputs and effects remain exact. Keep frozen oracle inputs untouched; list any
resource-inconclusive checks. E008 is used, never a new E010 depth diagnostic.

## Alternatives

Exact machine-frame/call-depth accounting was rejected by the maintainer: it adds
proof obligations and optimizer restrictions absent from ordinary application
languages. A counter in the callee prologue cannot prevent large-frame overflow.
A blanket signal-to-E008 handler is rejected because it hides real bad accesses.
Merely increasing the main-thread stack is rejected: no isolated guard geometry,
no configurable portable execution stack, and no alternate-stack diagnostic.

## Preregistered forecasts and gates

- Reported 200,000-depth recursion: no signal at O0/O2; E008 or correct completion
  if the larger stack suffices. Forced-small-stack/deeper variants must reach E008.
- Depth admission matrix: **36/36 non-divergent resource comparisons**, zero signals
  or build rejections; resource comparisons explicitly inconclusive, not exact solves.
- Existing native results/effects/non-resource diagnostics unchanged. CI >=551 tests;
  sanitizer suite >=250 plus the old large-record witness clean under ASan/UBSan.
- Add unbounded sequence, mutual and large-record recursion at 64 KiB/1 MiB/8 MiB;
  expect >=18 new resource-inconclusive O0/O2 comparisons per full seed, not a fixed
  code distribution. Always report actual E008 and E013 counts separately.
- Historical controls: native worker startup adds 0–0.5 ms whole-process overhead;
  forecast <=10% median change on append/scan/transform, measured alone.
- Natural/tuned qualification **19/150 and 22/150**, unchanged at this step;
  no ownership or language-expression change is credited to stack machinery.

## Consequences

Native stack use and reference call-depth accounting need not coincide. Existing
exact-depth tests remain useful for bounded counters where they do work, but
cannot define unbounded stack behavior. A guarded-stack diagnostic is a resource
failure, never proof of semantic correctness. Keep prior reports historical.

## Status

Accepted for Round 24 Part A; committed before compiler changes. Implementation
and gates must be reported separately before Part B begins.

## Dated audit amendment — 2026-10-09, resource-only classification

Maintainer clarification: negative sequence/record-buffer lengths are deterministic
validation failures, **E014 at the constructor span**, before byte-fill validation.
They are not allocation failures. Audit every E013 site: actual allocator failure,
nonnegative address-space/capacity overflow and the configurable memory guard stay
E013; impossible private width/capacity invariants become assertions, not resource
diagnostics. This intentionally corrects the earlier negative-length classification.

Removal audit for E013 (no quota-semantic work):

| Component | Sites | Verdict |
| --- | --- | --- |
| Reference `application.rs` | negative constructor length | E014 |
| Reference `evaluator.rs` | negative record-buffer length | E014 |
| Native `nil_make`, sequence/record allocators | negative length | E014 |
| Native allocators | zero physical width, capacity below length | assert validated internal invariant |
| Reference `application.rs`, `collections.rs`, `keyed.rs`, record evaluator | nonnegative size/capacity arithmetic, acquisition prefix, memory guard | keep resource E013 |
| Native sequence/record allocation, concat/growth, paths, reads, directory names | size/capacity overflow, malloc/realloc, memory guard | keep resource E013 |

Whenever either original outcome is E008/E013, rerun **both** paths from fresh
fixtures with memory, reference depth, native stack and execution budget scaled
4x together. Compare the rerun pair, never an original failure with a successful
rerun. Still-resource pairs remain inconclusive, counted by native-only,
reference-only or both and code/family. Exception: if the original reference
succeeded and native still reports E013 at 4x, fail the campaign as an accounting/GC
regression. Persistent native-only E008 remains inconclusive (frame sizes differ).
Report escalations, resolved-and-matched pairs, persistent directions and rule-3
failures. Signals, timeouts, malformed diagnostics and sanitizer findings always fail.

Input preservation and host-effect checks run before resource classification on
every original and escalated execution. Native test drivers separate their return
rendering from host stdout using a private result-receipt file; normal CLI output
is unchanged. This prevents a successful return print from masquerading as a host
effect when the other implementation exhausts a resource. Tests exercise classifier
directions, fresh fixture replay and this output separation. The old 88 E013
comparisons per seed are historical, not admitted evidence after this amendment.

Record-buffer std swap/pop remain E007: child ownership has not been proved.

### G1-1 diagnosis (before chained-update work)

Natural Validate BST updates `b[c:d]` inside a sequence-valued lazy arm. The
subsequent scalar reads `b[c-1]` are in the enclosing loop-step scope, not in that
arm's SSA instruction list. `ownership::replay_intervals` examines a replacement
and subsequent scalar observations within one list; `read_replay` admits only
scalar-valued lazy regions. It therefore cannot cache the outer observations and
retire the parent capture here. The parent root stays live while the arm receives
a second root; `nil_set_unique` correctly falls back to a full copy. This is a
cross-region analysis limit, not an accounting or recycled-slot defect.

Minimal reproducer: `(v)=@(a,0,0;b<1;true?a[b:9]:a,b+1,c+a[b];c)`. Its emitted
IR retains the parent root across `nil_set_unique`, with no `nil_set_replay` call.
The original must still produce the later scalar observation. Fixing this needs
a proof spanning the enclosing simultaneous loop-step list and the selected
sequence-valued region. No G1 implementation or narrow recognition is added in
this round's diagnosis. Part B changes contiguous update chains only, so it must
not be credited with removing this separate loop/lazy-region limitation.

The natural BST's later `b[c-1]` reads are specifically in `d==-1` arms,
mutually exclusive with the `d!=-1` update. Its measured copies are therefore
avoidable on the executed path. Parent liveness unions both arms and does not
carry this correlation into the nested update region. A closer reproducer is
`(v)=@(a,0,0,true;b<1;d?a[b:9]:a,b+1,d?c:c+a[b],d;c)`: emitted IR still
retains the parent root across `nil_set_unique` (no replay call). Thus this is
both a cross-region and path-sensitivity gap, not evidence of a runtime ownership
violation. The earlier unconditional-read witness demonstrates the broader
boundary, but must not be used to label the natural BST copies REQUIRED.
