# ADR 033 — Oracle-comparable host capabilities

## Context

ADR 026 requires a smaller compiler-visible contract instead of adding library
algorithms to HIR. Source providers cannot invent host privileges. The 13 remaining
unsupported corpus tasks mix missing execution capabilities with unfinished
adapters; their historical gap labels are not proofs of inexpressibility.

## Decision

Add three expr-v5 host primitives, retaining all existing profiles and defaults:

| Operation | Signature | ADR 026 verdict |
|---|---|---|
| env | Bytes -> Bytes | Core ordered environment effect plus owned result; a source provider cannot observe the process environment |
| random | () -> u64 | Core ordered entropy-state effect; PRNG mathematics can move outward, but acquiring/injecting entropy requires a Host contract |
| directory | Bytes -> MapI64 | Core ordered directory acquisition plus owned storage; filtering, recursion and metadata interpretation remain library work |

Intrinsic enum count changes from 32 to 35 (including Equal, whose source spelling
already lowers to a provider). There are three new semantic host contracts and no
new types. Each operation is non-borrowing, not pure, and may trap. Source modules
may use them with the caller's Host; borrow-only plugin providers must reject them.
No user-authored effect declaration can override these facts.

### Randomness

Host::random returns the next u64. A reusable seeded Host wrapper forwards other
capabilities and implements SplitMix64: add 0x9e3779b97f4a7c15 modulo 2^64, xor-shift
30 and multiply 0xbf58476d1ce4e5b9, xor-shift 27 and multiply
0x94d049bb133111eb, then xor-shift 31. Reference and C use identical wrapping
operations. Each successful selected call advances once; lazy unselected arms do
not acquire entropy or advance state. This is not cryptographic randomness.

The opt-in filesystem Host obtains an initial 64-bit seed from /dev/urandom on
supported Unix platforms, on first use; native does likewise. Native execution
can instead inject a canonical decimal u64 through NIL_RANDOM_SEED. A malformed
seed reports E016 on first selected random call, after host permission. Tests and
the differential oracle always inject a seed in both paths, compare exact u64
values, and never compare independently acquired OS seeds. No operation is exempt
from oracle validation. Unsupported entropy platforms report E015; no silent
clock/fixed-key fallback. Native arena cleanup resets RNG state for a new execution.
DeniedHost and unspecified Host methods report E018, including randomness.

### Environment and directories

Host::env accepts raw name bytes; NUL, empty name and '=' report E017 before host
permission. A missing variable returns empty Bytes, deliberately indistinguishable
from a present empty value. Unix values preserve OS bytes, including non-UTF-8.
Lookup/host failure precedes owned-result quota admission (E013). Environment
mutation, expansion, enumeration and Unicode conversion are excluded.

Host::directory returns immediate entry-name bytes, excluding '.' and '..'. The
compiler sorts by unsigned byte lexicographic order, yielding an insertion-ordered
MapI64 of name -> 0. Names are relative basenames, not joined paths; entries include
files, directories and symlinks without following them or acquiring metadata.
NUL in the input path reports E017 before permission; missing/unreadable/not-directory
paths and iteration/close failures report E015. Successful acquisition precedes
result quota admission. The result uses existing map capacities: entry capacity
starts at 4 and doubles, byte capacity starts at 16 and doubles, charged as
40+24+64*entry_capacity+byte_capacity. Host scratch is not a NIL value, as with
read; no scratch pointer escapes. Concurrent directory mutation yields an observed
snapshot, not an atomic filesystem snapshot. Fixtures stay immutable during tests.
Recursion, globbing, permissions metadata, file watching and recoverable I/O are
excluded. Windows OS-byte fidelity is not claimed.

Operands evaluate left to right before validation/effects. Structural checks
precede E018 denial; acquisition errors precede final E013 allocation. Errors reuse
E013/E015/E016/E017/E018; no parallel error space. Existing limits/checks remain.

Thus the overseer's host/core classification is refined: multi-file fixtures are
not a missing language module or new read capability, and reactive integration is
not honestly solved by a sequential plugin adapter. This backlog describes task
contracts, not a promise to implement every requirement in core. No library-side
capability is added this round. Corpus tasks, expected outputs and baseline sources
stay frozen; an adapter requirement can keep a task unsupported after its host
precondition is supplied.

## Alternatives

OS entropy without injection makes exact differential testing meaningless. Always
using a fixed seed misrepresents entropy tasks. A pure random(seed,index) intrinsic
would be a library algorithm, not a necessary host capability. Unordered readdir
results break deterministic oracles. Packed delimiter strings introduce an avoidable
encoding protocol where existing typed keyed storage suffices.

## Consequences

Native code and FileHost remain trusted and unsandboxed. Environment and directory
access add privileges, not safety boundaries. Custom Hosts can restrict them and
inject exact fixtures. C runtime remains the native semantics authority, validated
against an independent reference implementation. Successful random values do not
allocate; env/directory results participate in the existing arena/quota/root rules.
No allocation-free borrowing summary may include these host effects.

## Status

Accepted before implementation; implementation and measured results pending.
